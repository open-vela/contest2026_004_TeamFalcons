# VelaGuard Domain

VelaGuard is an independent industrial edge AI gateway context. This glossary fixes the project language used in manuals, plans, firmware modules, cloud services, and UI copy.

## Language

**VelaGuard**:
The STM32H750B-DK based industrial edge gateway that owns local sensor acquisition, local alarm decisions, local UI, and controlled cloud AI interaction.
_Avoid_: AI screen, chat terminal, PC sidecar demo

**Local Safety Loop**:
The offline-capable loop of Modbus acquisition, local rule evaluation, UI alarm display, and local logging. Planned phone speech is a network-assisted interaction channel and is not required by this loop; board-side alarm sound is outside the current scope.
_Avoid_: demo loop, fallback-only path

**AI Bridge**:
A removed historical cloud service that subscribed to VelaGuard MQTT requests, called MiMo, and published MQTT responses. Current operational AI uses board-side ai_agent HTTPS access to MiMo. Planned PDF parsing and phone speech services do not restore this MQTT bridge.
_Avoid_: sidecar, MiMo API, broker

**MQTT Broker**:
The message broker between VelaGuard and cloud consumers (dashboard, optional future OTA). It routes topics and enforces client access rules. Current contest broker is plaintext `8.148.67.174:1883`.
_Avoid_: AI Bridge, cloud API

**Device ID**:
The stable identity used in MQTT topics, authentication, logs, and cloud routing for one physical VelaGuard device. Current firmware uses `vg-` plus 24 lowercase hex digits of the STM32 96-bit unique ID; MQTT `client_id` is the same string.
_Avoid_: display name, sensor id

**Display Name**:
A user-facing label for a device or sensor that may change without changing identity or access rights.
_Avoid_: device id

**Sensor Configuration**:
The executable definition of how VelaGuard reads a sensor and evaluates its local alarm rules.
_Avoid_: prompt result, manual notes

**Candidate Configuration**:
A proposed sensor configuration that has not yet passed device-side validation and local confirmation. Planned phone/MQTT imports skip test reads and join normal acquisition after confirmation; the existing NSH workflow still requires a separate test read and human confirmation.
_Avoid_: active config, AI config

**Local Confirmation**:
An explicit operator approval on the VelaGuard device before a configuration or risky action becomes active.
_Avoid_: remote approval, AI approval

**Manual Import**:
用户为一个目标网关和从机地址提交手册、解析并选择测点的业务过程。网关暂时离线不妨碍准备候选。
_Avoid_: 配置已生效、一次 MQTT 消息

**Parse Result**:
一次手册解析得到的型号、测点及原文依据。重新解析产生新结果，不等于设备能力已验证或配置已获确认。
_Avoid_: 已确认点表、传感器实测值

**Point Selection**:
用户从当前解析结果中选择一个型号和一组受支持测点，形成准备下发的候选范围。
_Avoid_: 寄存器编辑、本地确认

**Configuration Attempt**:
用户一次主动下发及其板端处理结果。结果暂时无法核对时不能将其视为失败并自动重新添加。
_Avoid_: 手册解析任务、网络重连

**Configuration Session**:
板端为一次候选接入提供的独占、有时限的处理窗口，包含校验和本地人工确认。
_Avoid_: 登录会话、MQTT 连接、AI 会话

**Candidate Revision**:
同一配置会话中候选内容的版本。新版候选受理后，旧版人工确认失效。
_Avoid_: 固件版本、网页更新时间

**Configuration Applied**:
板端已将人工确认的配置持久化并用于正常采集。传感器是否在线及其读数由之后的实际通信确定。
_Avoid_: 消息已发送、传感器已在线

**Alarm Interpretation Session**:
An Agent session started when a rule-engine alarm is raised (event-driven), which gathers alarm context and live values to produce a human-readable explanation marked as AI-generated.
_Avoid_: fault triage, diagnostic ticket, troubleshooting session

**Operations Report**:
A daily or weekly summary generated by the Agent on a schedule, aggregating alarms, key metrics, and notable events from local stores.
_Avoid_: dashboard export, manual spreadsheet

**Natural Language Query**:
An interactive question answered by the board Agent using read-only tools and actual data timestamps. Existing CLI/UI entry points and planned phone speech must be identified separately; queries do not grant configuration or confirmation permissions.
_Avoid_: pure chatbot, open-ended Q&A without tools

**Active Alarm**:
An alarm instance that has triggered and has not yet met its restore condition.
_Avoid_: acknowledged alarm, historical event

**Acknowledgement**:
The operator action that records awareness of an active alarm; it does not mean the condition has recovered.
_Avoid_: resolution, close

**Resolution**:
The state transition when an alarm's restore condition has been satisfied.
_Avoid_: acknowledgement, silence

**Offline**:
A Modbus device state where normal reads have failed and VelaGuard switches to low-frequency probing while preserving prior alarm state.
_Avoid_: disabled, removed

**Recovering**:
A Modbus device state where full reads have resumed but VelaGuard waits for consecutive successes before returning to online.
_Avoid_: online, degraded

**Pending Event**:
A locally stored event that still needs reliable cloud delivery after network or MQTT recovery.
_Avoid_: MQTT session, retained message

**Retained Status**:
The latest retained MQTT status message that represents current device state for late subscribers.
_Avoid_: retained request, retained telemetry

**MQTT-only OTA**:
A superseded design that used MQTT/TLS for both update control and firmware chunks. Retained only as the historical term in ADR 0005; replaced on 2026-10-18 by ADR 0006.

**MQTTS Control + HTTPS Download OTA**:
The accepted, not-yet-implemented update design: MQTTS carries offers and status, HTTPS streams the image to eMMC, and the internal-flash boot stub installs it to QSPI after verification. Startup confirmation and failure recovery require separate implementation and tests.
_Avoid_: MQTT firmware chunks, direct writes to executing QSPI, assuming existing MQTT or HTTPS support means OTA is complete

**Board Hardware Pack**:
The local official STM32H750B-DK materials under `F:\Project\Embeded\H750B-DK\BOARD INFO\H750B-DK` (schematic, manufacturing, ST `bsp/`). **Use when** development depends on the real board circuit (drivers, pinmux, peripheral bring-up, expansion wiring). Then follow `docs/agents/BOUNDARY.md` **V11** priority. Files named `*_unofficial*` are non-authoritative notes that require cross-check. Not required for non-hardware work.
_Avoid_: web-only UM scrape, third-party pinmux gist, unofficial CSV as sole evidence when the local pack applies

**OTA Offer**:
A cloud-published proposal that describes an available firmware update before VelaGuard accepts or downloads any chunks.
_Avoid_: firmware image, forced update

**Staging Image**:
A downloaded firmware image stored outside the currently running firmware slot until signature verification and boot switching.
_Avoid_: active firmware
