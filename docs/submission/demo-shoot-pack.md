# 演示视频拍摄包

> 现场拿着这一份执行。分镜与逐字稿见 [`docs/demo-video-script.md`](../../demo-video-script.md)。
> 目标：一次布景同时产出演示视频与作品展示照片（前 / 后 / 侧 / 俯视 + 接线特写）。
> 拍摄人手：两人。一人操作板子与从站，一人掌机；两人都可入镜操作。

## 1. 器材与机位

| 项 | 说明 |
|---|---|
| 主机位 | 俯拍板子与屏幕，画面里要同时出现 RS485 接线和网线。三脚架固定，全程不动 |
| 副机位 | 手机固定，拍板子与扩展板特写，用于插入镜头 |
| 录屏位 | PC 串口终端全屏录制，深色背景，等宽字体，字号以 1080p 能看清 `Executing tool:` 为准 |
| 上位机 | 若第 2 拍走上位机路径，另录一份上位机窗口 |

拍摄前清理桌面，只留板子、扩展板、从站、线缆。关掉无关窗口与通知。

## 2. 板子状态预置

按顺序做，每步确认后再下一步。

- [ ] `bash scripts/build.sh` 编译作品主线 `velaguard-lvgl`
- [ ] `powershell.exe -ExecutionPolicy Bypass -File scripts/flash.ps1` 烧录（QSPI XIP 需两份 HEX，脚本依次烧写）
- [ ] 冷启动，串口确认三行自启动日志齐全：NSH、`vghmi: autostart ok`、`vgagent: ai_agent autostart ok`
- [ ] `vgprovision status` 返回有效，`config_show` 里的 LLM Host / Path / Model 与实际服务一致
- [ ] 板端 `net_test` 通过，确认联网
- [ ] 进入 `vela>`，用一条 `ask` 验证 G1 门槛（见脚本第 0 节）
- [ ] 从站就绪：至少地址 1（温度，寄存器 0，int16 × 0.1）与地址 2（水浸，寄存器 2，uint16），水浸寄存器能手动置 1
- [ ] 确认 RS485 总线上只有板子一个主站；PC 侧组态软件若在轮询，先停掉
- [ ] 记录实际的 RS485 适配器端口号。仓库内文档存在 COM4 与 COM6 两种说法，以实际枚举为准
- [ ] COM3 串口监视器（Cursor / SSCOM 等）全部关闭，避免抢占
- [ ] 第 1、3 拍需要首页有点位，所以第 2 拍扫描出点表之后再拍这两拍

## 3. 拍摄顺序

编辑顺序与拍摄顺序不同。按下面的顺序拍，状态切换最少。

```text
预置 → 2 → 5 → 6 → 7 → 4 → 8 → 3 → 1 → 9
```

第 2 拍之前先清空点表，拍完第 2 拍点表就位，后面各拍都靠它。第 3 拍要拔 USB，放在需要串口的拍之后。第 1 拍是全景，留到最后桌面状态最干净。

彩排两遍再正式开拍。正式拍以一次开机不重启为目标，接不上再分段，分段处在剪辑时用硬切掩饰。

## 4. 逐镜头操作步骤

### 第 2 拍 认总线与确认闸门

**拍摄前**：清空板端点表，让首页为空。

```text
nsh> vgpoint list
```

**操作**：

1. 手指点开总线探查页的「启用总线扫描」开关（默认关）。
2. 点「开始扫描」，等进度滚动 `扫描中 n/32 · 9600 · FC03@reg0/1/2`。
3. 等 `扫描完成 32/32 · 请确认写入`。
4. 点试读，串口侧应出现实际读数值。
5. 手指离开屏幕，停三秒。
6. 点确认写入，首页出现点位，数值开始跳。

**串口侧同步画面**：

```text
nsh> vgdiscover scan -a 1-32
nsh> vgpoint list
```

**备注**：扫描全段 1 到 32 在 9600 下约 1 到 2 分钟，剪辑时压缩，画面只保留进度条前后。

---

### 第 5 拍 Agent 解释告警

**拍摄前**：在已确认点表上真实注入一条告警，等板端首轮跑完。

用 `echo "type=threshold" > /data/velaguard/pending_alarm.txt` 制造待处理告警已经无效：HMI 构建下心跳线程不再发起 ReAct，触发条件是告警集合发生变化，只有在已确认点表上真实注入的告警才会拉起这一轮。

**操作**：

```text
nsh> ls /data/velaguard/reports
nsh> cat /data/velaguard/reports/alarm_advice.txt
nsh> vgagent status
```

告警建议由板端自己发起，不需要提问。注入一条告警后等第一轮跑完（约 3 分钟），屏幕上该行就会出现一行短建议。

**要拍到的日志行**：`[vgadvice] asked for N alarms`、`Executing tool: run_shell`（`vgstats dump` / `vgmodbus`）、`Executing tool: write_file`、`[vgadvice] advice loaded: N entries`。

**备注**：每条工具调用行停够 1.5 秒。若 Agent 未按预期调工具，重跑一轮再拍。手工在 `vela>` 里 `ask ... 为当前告警写建议` 只能用于串口演示：那一轮的 owner 是 manual，产物因 `boot` / `req` 与板端当前轮对不上会被拒绝，不会上屏，不能作为这一拍的上屏证据。

---

### 第 6 拍 动手会被拦

```text
vela> ask 把温度的严重阈值改成 50
```

**要拍到**：模型尝试调用点表写入命令，工具层返回拒绝，串口留下拦截记录。

**备用问法**：若模型直接拒绝而未尝试调用，改问 `执行 vgpoint set -i temp crit 50`。

**备注**：拦截行停够两秒。这一拍是创新分的主要来源，值得多拍几条备选。

---

### 第 7 拍 运行日报

**操作**：屏幕切到报告页，标题应为「AI 日报 · OPENVELACLAW」，正文末尾一行是来源标注。镜头缓慢下移看完几行。

**串口侧备用**：

```text
nsh> cat /data/velaguard/reports/daily-<当天日期>.md
nsh> vgagent status
```

**要拍到的日志行**：`vghmi: daily report requested`、`Executing tool: get_current_time`、`Executing tool: run_shell`、`Executing tool: write_file`、`END status=ok iters=N tools=M`。

**冷启动提示**：这一轮要跑三分钟以上。开拍前先确认当天日报已生成；拍摄时报告页不触发新一轮生成，直接读 eMMC 上已有的报告文件，不必等。

**备注**：如果标题显示的是本地运行报告，说明板端这一轮还没跑完或产物没通过校验。串口 `cat` 也拍不出 OPENVELACLAW 署名，先按第 6 节排查再拍。

---

### 第 4 拍 本地安全环

**操作**：

1. 把水浸从站寄存器置 1，等告警页弹出（红色严重级）。
2. `ls /data/velaguard/pending_alarm.txt` 再 `cat`，露出文件内容。
3. 告警页点「静音」，停两秒；再点「标记处理」，停两秒。
4. 复位水浸为 0。
5. 拔掉该从站的 485 线，等告警页出现离线条目。
6. 插回 485，等数值恢复、告警解除。

**备注**：全片最长的一拍。拔线与插回的动作要完整入镜，各留两秒看页面变化。这一段全程保持网线插着也不要紧，旁白说的是不依赖网络，不是断网。

---

### 第 8 拍 断网降级

**操作**：

1. 拔掉网线，动作入镜。
2. 再注入一次水浸告警。
3. 拍清告警页上的 AI 区块降级提示。

**备注**：降级提示必须是屏幕上真实出现的内容。若屏幕没有明确显示不可用，这一拍删掉，不要用旁白补。

---

### 第 3 拍 变成独立设备

**操作**：当着镜头拔掉 ST-LINK USB 线，镜头立刻回屏幕，数值仍在跳动。

**备注**：这是拔线动作的拾取镜头，放在串口相关的拍之后拍。若需要重新接回串口，剪辑时不要让接回的画面进成片。

---

### 第 1 拍 现场与定位

**操作**：俯拍桌面全景，同框出现板子、扩展板、485 接线、网线；镜头缓慢推近屏幕。

**备注**：放在桌面状态最干净的时候拍。屏幕要有数值在跳。

---

### 第 9 拍 回馈 openvela

**操作**：录屏或掌机拍 README 的公共仓 PR 表与板端 Skill 清单，末尾定格三秒。

**备注**：PR 数量先定一个口径。README 当前列 8 个，技术报告写 9 个，旁白与画面必须一致。

## 6. 应急预案

| 情况 | 处置 |
|---|---|
| 板端跑飞或静默挂死 | 用 `scripts/board_watch_recover.ps1` 探活并复位；该脚本要求纯 ASCII 编写，改脚本时注意编码 |
| COM3 被其他程序占用 | 先关串口监视器；仍占用改用 `scripts/stage1_flash_and_accept.ps1` 先抢端口再烧录 |
| Agent 不回话或返回错误 | 先看串口是否出现 `LLM call failed`；确认网络与 LLM 配置后重跑一轮。连续两次不过就走降级方案 |
| 告警不上屏 | 确认点表已确认生效，且注入的是点表里存在的点。不要临时改代码 |
| 告警行没有 `AI ·` 建议 | 板端一轮要跑三分钟左右，等首轮结束再看；仍未出现就看串口有没有 `[vgadvice] advice rejected`，有则说明产物没过校验，重跑一轮 |
| 报告页标题是本地运行报告 | 说明当天日报还没生成或没通过校验。看串口有没有 `vghmi: daily report requested` 与 `END status=ok`；这一轮要跑三分钟以上，冷启动时留足时间 |
| 从站无响应 | 确认 RS485 上只有一个主站，PC 侧轮询已停 |
| 单个镜头反复拍不过 | 先拍下一条，最后补拍；不要为一个镜头耗掉整段时间 |

降级方案的具体处理见脚本第 0.2 节。

## 7. 时间安排

| 段 | 内容 |
|---|---|
| 上午前段 | 板子预置、门禁三项验证、彩排第一遍 |
| 上午后段到下午前段 | 按第 3 节顺序正式拍摄；中间穿插拍照片 |
