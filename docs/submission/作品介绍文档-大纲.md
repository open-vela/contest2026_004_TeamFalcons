## 2. 一段话定位

**VelaGuard 是一台独立运行在 STM32H750B-DK 与 openvela 上的 RS485/Modbus 现场网关。它的核心不是采集转发，而是把已采集的数据讲给人听。**

采集、告警、帧统计与配置存储由板上确定性 C 代码完成，断网照常。板载 `ai_agent` 负责告警解释、运行报告与自然语言查数，按只读 Skill 执行，点表提交命令在 C 工具层被拒绝。

目标用户：要把设备接到陌生 485 总线上的嵌入式工程师、自动化调试与系统集成人员。

取材：README「这是什么」「它解决什么问题」。对应视频第 1 拍。

## 3. 用户故事

三段故事，各对应一条主线。每段按「谁在什么场景下、解决什么问题、看到什么结果」写，不写功能罗列。

### 3.1 接入陌生总线

集成工程师带着网关到现场柜子，不知道总线上有几个从站、地址是多少、寄存器该怎么解读。在屏上打开总线扫描开关（默认关闭），扫地址 1 到 32，探测寄存器块，生成候选点表；测试读取通过后现场确认，曲线开始跑。全过程本地完成，不需要网络。

对应视频第 2 拍。取材：README「它解决什么问题」第 1 条、手册 §7。

### 3.2 夜里温度越限

规则引擎在板上判定阈值或离线告警，屏幕立刻报警，不等网络。联网时板端在告警集合变化后自己发起一轮，Agent 调只读命令取证，把逐点解释写进 `alarm_advice.txt`，屏幕上每个告警行都带一行建议，详情区是可展开的完整解释并标注「AI 推测」。工程师早上看到的是解释，不是一串原始数值。

对应视频第 4、5 拍。取材：README「它解决什么问题」第 2 条。

### 3.3 主动生成的当日运行日报

板端发现时钟已同步、当天还没有日报时自己发起一轮，Agent 按 `operations_report` Skill 用 `get_current_time`、`vgruntime dump`、`vgstats dump` 取真实数字，写出 `daily-当天日期.md`。板端校验通过后 LVGL 报告页标题显示「AI 日报 · OPENVELACLAW」，断网或校验不过则回退固件统计报告并标注本地来源。随时可以在 `vela>` 用自然语言查当前读数。

对应视频第 7 拍。取材：README「它解决什么问题」第 3 条。

## 6. 技术实现

按「架构分层、数据流、关键机制、硬件、交互、Skill」六段写。详版见技术报告 3.2 到 3.4，本节只列结构，避免重复。

1. **架构分层**：应用层（采集、告警判定、点表、运行时统计）、界面层（LVGL 模型与页面）、Agent 层（`ai_agent` 与 Skill）、系统层（openvela / NuttX）。
2. **数据流**：采集 → 帧统计 → 规则判定 → 待处理告警文件 → Agent 按 Skill 取证 → 解释落盘 → 界面读取。
3. **关键机制**：本地安全环、候选点表试读后人工确认闸门、C 工具层只读边界。
4. **硬件**：H750B-DK 加扩展板，RS485 收发器与 120 欧终端、ESP-01S 备链路、数字量输出、eMMC。
5. **交互**：LVGL 触控为主，CLI `vela>` 自然语言查数为辅。
6. **Skill**：`alarm_interpretation.md`、`operations_report.md`、`modbus_query.md` 三份的触发条件、允许工具与产出。

对应视频第 4、5、6 拍。

## 8. 写作口径与禁止事项

1. 每个「已落地」都要能在仓库里指到文件或板测记录。指不到的写进阶段 2 或阶段 3。
2. 区分设计目标、已实现、历史板测与本次尚未验证的能力，不混写。
3. 未测项目如实标注。24 小时连续运行、告警注入命中率、物理拔插时延、功耗、实体触摸帧率均未测。
4. 不使用未经本次复核的性能数字。历史记录引用时必须带日期与当时条件，例如 2026-08-30 单次 `ask` 的时延与轮次数是单次样本，不是平均时延，也不是带屏固件的数字。
5. C 工具层已把只读限制细化到子命令：`vgstats`、`vgruntime`、`vgcfg` 只放行 `dump`，`vgnet` 只放行 `status`，会改板端状态的子命令已被封住（与 README「Agent 安全边界」、技术报告 3.7 一致）。
6. 不使用中文弯引号，除非逐字引用。
