## 逐页

### 1. 封面（14 秒）

评委好，我是叶培林，代表 Team Falcons 汇报 VelaGuard。它是一台独立运行的监测网关，跑在 STM32H750B-DK 和 openvela 上，本地做规则值守，板载 Agent 负责解释真实数据。

### 2. 一个小机房的一天（32 秒）

先说它每天怎么被用。早上七点四十交接班，一屏看到 14 个点位在线、4 条活动告警、0 个离线。右边这块屏幕是本地渲染的模拟界面，读数和时间线来自同一份快照。九点十五接入新电表，从站地址 3、保持寄存器 0、倍率 0.1，逐项写进候选表。十点十二回风温度到 83.2 度，越过 80 度阈值，规则在本地判定并上屏。一分钟后 Agent 只读取值，把空调故障、采样异常和通信中断分开。下午四点半交班复盘，日报落盘。时间线是示例，越限数值来自台架模拟从站。

### 3. 架构与任务（28 秒）

一台 H750 上分四层：云端与网络、板载应用、openvela 组件、硬件。要强调的是右边这六个任务：优先级和栈都是构建期常量，ai_agent 32 KiB，vghmi 48 KiB，采集线程挂在 vghmi 里，8 KiB。语音任务优先级 110，按键录音 90，都在同一个调度器里排队。

### 4. 采集链路与点表闸门（38 秒）

从一帧 RS485 开始。9600 8N1，半双工，帧级 CRC。Modbus 主站独占总线，14 个点位一轮扫完。点表闸门：add、set、del 只写候选表，apply 必须带 --confirm，人执行后才写已确认表。板端实录 14 行 READ 全部 ok=1；缺 --confirm 返回 need_confirm，退出码 1。采集线程点间 50 毫秒，读超时 500 毫秒，失败重试一次，轮末 200 毫秒，锁忙跳过本轮。

### 5. 对外接口（26 秒）

这是板端对外开放的六个接口。上位机 ST-LINK VCP，115200，vgpoint 八个动词，32 点；看板 1883 测试链路，四条上行主题；候选配置走 TLS，板端已跑通，云侧待接入；OTA 走 MQTTS 和 HTTPS，offer 1536 字节；手机上传和语音巡检接口已定；南向 RS485，9600，单主站，14 点。

### 6. Agent 一轮（30 秒）

告警进来之后 Agent 走一轮 ReAct：触发、载入 Skill、LLM 规划、工具调用，结果回填上下文。一轮最多 10 次迭代，每次响应最多 2 个工具调用，这两个数都在 agent_config.h 里写死。三个上限：60 秒 20 次调用，单轮 300 秒截止，Agent 栈 32 KiB，TLS 和 JSON 同在一条栈上。右下是设备上的自然语言问答，问题、答案和背景读数都是模拟会话。

### 7. 只读边界（28 秒）

只读不是提示词，是 C 代码。注册层只放 5 个只读工具，vgpoint、vgcfg、vgdiscover apply 根本不注册。运行层在 C 里强制参数和频率：点位查询超过 48 字节直接拒绝，输出上限 2048 字节，列表最多 12 条。审计层每次执行都计数，写 /data/velaguard/logs/agent_tools.log，单文件 64 KiB 轮转。

### 8. 端到端时序（26 秒）

这是同一条告警的端到端时序。规则引擎写事件、投递任务，ai_agent 带上 Skill 和工具表请求 MiMo，模型回 tool_call，板端执行只读工具读采集快照，结果回填，最终 JSON 经 schema 校验后上屏并写 alarm_advice.txt。8 条合计 41.83 秒，工具取数只占 1.96 秒，而且读的是快照，不占 RS485。

### 9. 断网行为（26 秒）

网络断了会怎样。RJ45 拔掉，采集、判定、上屏、事件落盘照常。MQTT 断开时告警进 8 条 RAM 队列，满了丢最旧，重连补发，断电不补。MiMo 超时就不生成解释和日报，屏幕保留本地规则和真实读数。从站离线按 8 个样本里失败 5 次判定，一次成功采样即恢复。

### 10. OTA 两面（30 秒）

OTA 把控制面和数据面分开。控制面走 MQTTS 8883，订阅一个主题、发布三个，全部 QoS 1。固件走 HTTPS，出口绑定 eth0，明文 MQTT 不承载 OTA。下载后依次校验 TLS 证书链、offer 九字段、清单 512 字节加 CRC、ECDSA P-256 签名、型号版本和 SHA-256 回读。安装只认屏幕长按 2 秒或按键，其它来源的确认请求返回 -EPERM。

### 11. 双槽回滚（26 秒）

双槽加回滚。QSPI 64 MB，A 槽是出厂固件，B 槽是试用固件，各 8 MB。状态机从空闲到收到 offer、下载、校验，然后停在本机确认，人长按之后才重启进 B 槽自检。自检不过或者看门狗 32 秒超时，直接回 A 槽，trial 3 次仍失败也回 A。BCB 是两份 4096 字节轮换，140 字节头加 CRC32。

### 12. 行业场景（22 秒）

回到现场。这类现场结构相同：点位不多、长期没人、仪表杂、网络不稳。整套 SCADA 改造大，人巡检又看不见夜里。我们加一台网关：485 唯一主站，规则在本地，断网照常判定，Agent 只读数据做解释。

### 13. 性能与资源（22 秒）

性能摊开看。一次告警解释平均 5.23 秒，8 条合计 41.83 秒，模型推理占 95%，工具取数只有 1.96 秒。语音首播中位 18.4 秒，30 条里 28 条在 30 秒预算内。Flash 占 1.13%，静态 SRAM 69.22%，60 秒窗口内的显示提交从 438 次降到 24 次。

### 14. 真机演示（4 秒）

这是 80 秒演示的四格分镜：首页、告警详情与 AI 建议、自然语言问答、运行报告。视频还没录制，播放时替换本页。

### 15. 进度（18 秒）

初赛之后补了四块：稳定性修复、语音链路、双槽回滚和 OTA 控制面，再加答辩工程。下一步是手机上传手册接入、手机语音巡检、24 小时连续长测和生产信任与凭据，其中前三项都还没有验收记录。
