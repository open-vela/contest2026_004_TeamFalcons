# MQTT候选接入与板端人工确认

状态：用户已选择MQTT传输，并更正为板端不显示远程配置状态、仅在手机下发后进行板端二次确认；本文记录的协议细节为设计草案，待实现和验收。

日期：2026-10-18。

## 决策

用户选择通过MQTT传输手册解析后的候选点表，异常与恢复交由开发助手设计。按用户最新更正，手机接入不试读；远程配置状态只在手机显示，板端仅在手机下发且配置校验通过后弹出人工二次确认，确认后直接添加。每次修改产生新revision并使旧确认失效；该版本指候选版本，不指定现有文件或固件版本号。

手机PDF上传仍走受鉴权HTTPS接口。配置服务经专用MQTT主题发送候选和查询请求，板端返回状态；不提供试读操作。远程部署使用TLS、设备鉴权与方向隔离的ACL。当前明文MQTT上报能力不等同于已支持候选接入。

候选完成字段、能力、容量和冲突校验后，板端弹出对应版本的二次确认，展示必要的点位与手册依据；确认后持久化并加入正常采集，未确认不生效。添加成功只代表配置生效，实际通信及读数由之后的正常采集确定。MQTT没有远程apply或confirm，不赋予板载Agent配置权限。采用独立远程候选与配置会话互斥，保留NSH原有人工确认流程。

## 替代范围与限制

替代AGENTS V4/V6及手册中禁止MQTT传输候选的旧团队约束，仅开放本协议定义的确定性配置入口。原NSH仍是现行实现；不经RS485或第二路UART配置点表的限制保持。AI请求响应、语音、音频不因本决策获准走MQTT。

[ADR 0004](0004-ai-generated-configuration-requires-device-side-confirmation.md)的人工确认要求保持，原先对手机入口的试读要求由用户本次更正取消；NSH流程保持。[ADR 0006](0006-mqtts-control-https-download-ota.md)的OTA方案保持，其不开放MQTT候选的表述由本决策替代；OTA不提供配置通道。
