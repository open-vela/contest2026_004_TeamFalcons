# 流式播报恢复与重新缓冲验收

日期：2026-10-25。依据用户确认的实施方案：优先减少停顿，接受短回答收齐后播，长回答提前起播。
本次保留 `aed8599` 的按键录音交接修复，以及 `f00d22c` 的独立合成预算。

## 当前行为

- 发布配置恢复流式播放，环形缓冲 128 KiB，初始缓存 2500 ms 音频。
  `vgvoice prebuf` 可调 50–4000 ms，同时受环形缓冲实际容量限制；短于门槛的回答在 EOF 后播放。
- 环暂时为空时继续处理驱动缓冲归还，只有所有音频耗尽才算欠载。
  重新缓冲依次为 3000、3500、4000 ms；完整接收后立即排空剩余音频。
- 始终先填充已归还的缓冲再恢复消费，驱动未归还的缓冲不复用。
  驱动无进展超过在途音频时长加 1000 ms 时明确失败，不 STOP 后重灌不确定播放进度的数据。
- ASR 和查询共享 30 秒，首次合成另有 30 秒，用户重试为 15 秒。
  播放器启动接口接收绝对单调时钟截止时间；队列满时检查取消、截止时间及消费线程状态。
  EOF 后按实际 16 kHz 单声道输出音频时长加 5 秒排空，不沿用合成截止时间。
- 云端流式解码和完整缓存路径共用 512 KiB 原始 PCM 上限。失败、超限或截断停止播放并保留文字；
  播放器启动前失败可退回 WAV，启动后失败不重新合成。未回收会话返回忙时不再抢占设备走 WAV。
- 记录缓冲达标、启动、欠载、恢复、结束及失败信息，不记录原始音频和凭据。
  兼容字段 `played_bytes` 表示交给驱动的立体声音频字节，`returned_bytes` 表示正常归还的字节；
  只有完整接收、环排空、驱动全部归还且字节相符时才报告完整成功。

## 主机验证

`make -C app/velaguard/host_tests test` 通过，见 `host-tests.log`。
模拟驱动按真实音频时长归还缓冲，测试覆盖：2500 ms 起播、短句 EOF、在途音频期间不误报欠载、
3000/3500/4000 ms 重新缓冲、满队列超时和取消、驱动停滞、各阶段取消、连续下一轮、
EOF 后跨合成截止时间排空、设备启动失败、会话互斥及缓冲所有权。
采样图案使用非短周期序列，逐采样核对顺序、重复和遗漏。满队列测试使用有界线程等待。
云端测试另覆盖超过 512 KiB 时先拒绝再回调，失败时没有残留的半份 WAV。

### 已观察到的限制

`accept.log` 中两轮真实异常汇总长回答在当前网络下达到 30 秒合成上限，
已提前播放并出现重新缓冲，最终均明确报告部分播放失败。第三轮由测试脚本在查询阶段取消。
这些记录不计入完整成功样本，也不据此延长用户批准的预算或删减播报内容。
流式播放能提前出声；持续供给慢于播放速度时仍需等待，超过合成上限仍会停止并提示失败。
日志还包含既有后台告警任务的输出，本次未修改其规则、设备点表或公共驱动。
