## 硬件、格式与实现

本次读取本地官方 `mb1381-h750xb-b01-schematic.pdf` 的 Audio 页，核对 U34、MIC_CLK/MIC_DATA、WM8994 与绿色 CN9/HPOUT1；并复核资料包 BSP 的 PDM 初始化。继续使用已验证的 SAI1A 输入和 SAI2A 输出，没有改接线、引脚、PLL 或另开输入路线。耳机口不称为独立 Line Out。

- 输入保持当前驱动的 8 位 DMA、LSB 在前配置；每字节含 8 个滤波输入位。单路位流在内存中的有效到达率约 128 kB/s。
- 第一级为二阶 8 点滑动和，抽取 8；第二级为 129 抽头 Q15 FIR，再抽取 8；最后做约 20 Hz 的直流阻塞。状态跨块保留。
- 目标格式为 16000 Hz、单声道、16 位 PCM。回放写成 16000 Hz、双声道、16 位 WAV，单声道样本明确复制到左右声道。标准 NxPlayer 解码与播放路径实际接受了这些 WAV。
- 主机测试使用独立 Python 参考模型、任意分块比较、直流/满幅测试及非零抽取相位的容量拒绝回归，见 [host-tests-final.log](host-tests-final.log)。系数及响应可由 `python3 scripts/gen_pdm_filter.py` 重现，见 [filter-design.txt](filter-design.txt)。响应表的 8 kHz 点约 -61.89 dB，不能将少量频点当作整个阻带的实测保证。
- 字节率、样本数和时长只证明这条软件采集链的比例关系；没有逻辑分析仪实测麦克风时钟。位序和线路配置的人声可辨性仍需听音确认。

### ST 库核对与选择

核对本地 Cube H7 V1.13.0：`Package_license.md` 将 STM32_Audio 列入 SLA0048 Rev5；PDM 头文件仍引用 MCD-ST Image SW License Agreement V2。包条款列有 ST 处理器使用限制、再分发条件及禁止把该软件包改为受开源条款约束等要求，不能简单归结为非 Apache 所以禁止使用。

本地 CM7 GCC wc16 库的 ELF 属性为 Cortex-M7、FPv5、硬浮点参数、2 字节 wchar；当前固件为硬浮点参数、4 字节 wchar。后者是否影响调用还需按具体接口判断，不能仅凭属性差异宣告 ABI 不兼容。BSP 明确启用 CRC 外设时钟后初始化 PDM 库，并配置 64 倍抽取。没有实际链接或运行 ST 库，不宣称其适配已通过。

本轮沿用并修正原会话已写的独立整数滤波实现，便于在主机和板端验证同一份源码，无需分发二进制库或增加 CRC 依赖。未复制 ST 库源码或二进制进入交付物，也不声称 ST 库在本项目中必然不可用。

## 连续性、所有权与资源上限

- 16 KiB、32 字节对齐的 DMA 环形缓冲，半缓冲 8192 字节；配置为循环 DMA。每轮开始一次、停止一次，采集过程中不逐块重启 SAI。
- 回调将完成的半缓冲复制到 8 槽固定队列，不做滤波、打印、分配或等待。消费者处理完一块才释放槽位，DMA 不会修改该队列中的数据。
- 语音任务优先级从 95 调为 110，高于 HMI 的 100，低于高优先级工作队列的 224。空闲阻塞等待；录音和播放阶段使用有上限的等待。
- 驱动核对 DMA 当前半区，拒绝交付正被写入的区域；错误回调不伪造完成事件。结束后补交尾段，只有确认 DMA 和 SAI 都已关闭后才归还环形缓冲。
- 用每轮实际交付数核对：`samples = floor((halves * 8192 + tail_bytes) / 8)`，`drained = halves + (tail_bytes > 0)`。丢块、溢出、时钟错误、传输错误或序号异常会使非取消录音失败，不静默压缩时间。
- 固定 PCM 上限 496000 字节；PDM 队列约 65632 字节；DMA 环和 WAV 转换暂存各 16384 字节，总计约 594400 字节，不含任务栈、NxPlayer 和驱动自身缓冲。语音任务栈 4096 字节，命令队列 16 项。
- PCM 与队列在初始化时分配并复用，空闲仍保有固定预算。每轮结束清零本轮 PCM、PDM 队列、DMA 环和 WAV 暂存，并删除临时 WAV；真正关停且任务退出后再释放分配。
- 队列高水位本次为 1；滤波耗时最大观测为 10000 us、复制为 0。时钟分辨率也是 10000 us，0 仅表示未跨 tick，不能当作零耗时或微秒精度测量。
- 本轮没有专门注入 DMA 停止失败、消息队列卡住或内存分配失败，不将源码检查当作这些错误路径的板测。

## 并行回归与限制

- `13-fifteen-recovery.log` 在录音前、录音中和结束后记录了帧统计、运行数据、任务、内存；采集任务和超时计数持续推进。当前 14 个点均离线，不能证明在线读数正确。
- 原始输出中有 HMI 的周期 live 更新，HMI 任务仍运行。`vghmi perf` 本构建显示统计关闭；没有本轮触摸操作证据，不宣称显示/触摸已完整通过。
- eMMC 临时文件写入、读回、删除已完成。接口 eth0 为 RUNNING 且有地址；这不等于云服务可用。后台既有 Agent 返回模型不支持错误，本次没有修改模型或云链路。
- 背景 Agent 延迟初始化使内存从约 797 kB 增至约 880 kB，不能把跨这个阶段的差值直接算作录音泄漏。稳定阶段另做取消前后比较，堆使用量均为 880144 字节、nused 均为 1055，见 16-cancels-stable-resources.log。
- 语音和按键均只有一个常驻任务，播放线程在结束后不留在任务清单；临时录音目录为空。
- 播放 SAI 欠载仍出现。`15` 日志打断后计数为 30；先前 `11` 日志为 107。最终镜像三轮复验的欠载计数为 0，但一次未出现不能否定此前记录。原始 DMA 状态仍显示 `31`，FEIF 为既有已知观察，当前通用 DMA 回调不提供独立 FEIF 计数。不能宣称无播放错误，也没有证据说明它与轻微杂音同源。
