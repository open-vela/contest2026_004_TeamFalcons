状态：**基础播放、启停与触摸已验证，严格质量项未全部通过**。用户确认yes可辨认、停止重播正常；轻微杂音按用户意见延期。新固件修正触摸卡顿后，完成20次正常播放、10次主动停止和10次重播及基本并行回归，见 [最新验收](lifecycle-followup/README.md)。SAI欠载仍存在，不标记BVO-04全部完成；BVO-03继续未完成。以下保留早期固件与延期记录。

## 1. 输出接口与硬件依据

沿用用户授权的绿色 CN9 + WM8994 HPOUT1，极低初始音量。原理图、BSP、RM0433 和 WM8994 数据手册核查见 [前一日硬件记录](../../2026-10-21/bvo-04/README.md)。CN9 的 6/4 脚直接接 HPOUT1L/R；3 脚是 HPOUT1FB/地。C113/C114 经 R182/R183 接地，不是串联隔直电容。CN18/CN17 是独立的差分 SPK 左/右端子；没有原理图依据证明它们与 CN9 并联。旧 BVO-01 中关于并联的推断不再作为输出使能依据。本轮始终关闭 SPKOUT，未调整连接。

HPOUT1 是耳机输出，不称独立 Line Out。可接适配耳机或高阻抗有源音箱输入，先降低外接设备增益。用户口述实测可支持 HPOUT1 识别和跳线端子识别，不能单独证明不同网络之间的连通关系。

WM8994 与触摸共用 I2C4，目标为 7 位地址 0x1a。原理图 CS/ADDR 上拉 DNF，数据手册表119对应默认下拉时的 8 位写地址 0x34。板端 ID=0x8994 对照一致，只读指定器件，无无差别写探测。修复探针高寄存器地址被 uint8_t 截断的问题；16 位寄存器地址和数据都按 MSB first 传输。诊断临时取得的 I2C 引用已平衡释放。

## 2. 格式、时钟与实现

链路：NxPlayer → `/dev/audio/pcm0p` → 标准 PCM WAV 解码器 → WM8994 → SAI2 block A → HPOUT1。SAI2 PI4/5/6/7 分别为 MCLK/SCK/SD/FS；SAI1 PDM PE4/5 保留。PCM 数据为 16 kHz、16 位有符号小端、立体声，L=R，无隐式单声道转换；编解码器为 I2S slave、16 位、AIF1 timeslot0，SAI 为异步 master TX、两个 16 位时隙。

按标称 HSE 25 MHz 计算：

| 项目 | 配置或推算值 |
|---|---|
| PLL2 | M=25，N=344，P=7，保持 BVO-03b 参数 |
| PLL2P | 344000000/7 = 49,142,857.142857 Hz |
| 16 kHz 播放 | MCKDIV=12，NOMCK=0，OSR=0 |
| MCLK | 4,095,238.095238 Hz，目标 4,096,000 Hz |
| BCLK | 511,904.761905 Hz，目标 512,000 Hz |
| FS / 实际采样率推算 | 15,997.0238095 Hz |
| 相对误差 | -186.011905 ppm = -0.0186011905% |

没有仪器实测频率，以上不含晶振实际误差。结束后 WM8994 重置为默认 48 kHz，当前 CR1 分频回到 4；末次传输快照 CR1 的分频 12 才是上述文件播放时的配置。不能用空闲时的分频 4 判断 16 kHz 文件的播放频率。

RM0433 Rev9 §51.4.8、§51.6.2 明确 bit27 保留、bit19 名为 NOMCK。撤掉早期把其他系列 MCKEN 当成 H750 必需时钟门控的改动，删除错误位定义。只用本芯片已有的主模式和 NOMCK=0 生成 MCLK，不对从模式或同步模式加 MCKEN。本轮未重配 PLL2、PLL3 或系统时钟。

驱动接入和修复：

- 板级 WM8994 注册，启用专用缓冲信息；否则当前音频上层未取得缓冲数量时会拒绝分配，NxPlayer 在送入数据前退出。
- PCM 使用 I2S 的半帧声道标识、低有效 FS 和提前一位的帧同步；PDM 格式保留。
- TX 请求在取得缓冲和改变硬件前检查空长度、奇数长度、超容量及错误偏移；修复 setup 失败时队列/引用所有权及错误返回。
- 修复正常结束后 stop 向已关闭 WM8994 消息队列发送导致的 HardFault；stop 与 worker 关闭队列互斥，重复 stop 可返回。
- 正常模式 DMA TC 后，在中断中接续已经验证、持有引用的下一块 TX 缓冲；不分配、不等待队列、不打印。应用完成回调仍在 HPWORK。DMA 正常模式 TC 已清 EN，接续时不等待活动流结束。
- 最后一块在 worker 中有界等待 FIFO/移位器完成，再关 SAI；中断中不做排空等待。新增完成、TEIF/DMEIF、超时、字节数、SAI underrun 和时钟错误计数。

DMA 缓冲来自 cache line 对齐的标准 `apb_alloc`，禁止 DTCM，TX 做 clean，保留写透 D-cache。WAV 首块 44 字节偏移仍满足半字传输对齐。正常模式半字 DMA 计数上限 65535；当前 `apb_samp_t` 为 16 位，单个公开 APB 本身不超过 65535 字节，不能声称已从该 API 动态覆盖超过 65535 个半字的路径。DMA 句柄由持久板级设备持有；播放结束回收缓冲和任务，不把每次播放重新申请句柄当作资源模型。

注意：低层 DMA 实现实际在普通模式启用 FIFO full threshold，并非早期 SAI 注释所说的 direct mode。原始回调状态反复含 FEIF（0x01），已保留，不能宣称所有 DMA 标志无错误。低层代码注释说明 FEIF 曾被视为伪报而未使能其中断；这不是本轮证明它无害的证据。快照中的 DMA SCR/NDTR/地址是启动时保存值，不冒充硬件实时回读。

## 3. 样本和验收结果

已知文件与许可、生成方式、SHA256 见 [fixtures](../../2026-10-21/bvo-04/fixtures/README.md) 和 [SHA256SUMS](../../2026-10-21/bvo-04/fixtures/SHA256SUMS)。两份文件均 64044 字节、64000 PCM 字节、16000 帧、标称 1 秒。测试音 1 kHz、峰值 2047；语音是 TFLM `yes_1000ms.wav`，整数幅度除4后逐样本复制到 L/R。生成器可重现嵌入字节。板上文件由 `vgaudio fixtures` 固定写到 `/mnt/emmc/bvo04/`；本轮没有板端文件摘要读回。

初始化音量 raw10（HPOUT1 -47 dB，静音）；NxPlayer `volume 15` 是 15%，转换 raw9（约 -48 dB）。控制台参数不是 0..1000；之前的 `volume 300` 不能算低音量设置。没有声压级校准。

验收脚本 `scripts/audio_accept.ps1` 的所有命令等待有上限，失败保留串口记录，不自动复位或继续后续轮次。旧脚本的1秒存储等待曾误判；实际写回在4.33秒后成功。另一次诊断误用Cube CLI的 `mode=HOT`，工具回退Normal并发生软件复位，已保留警告。该操作不计入恢复通过证据，最终失败后未用复位清场。
