# 官方能力与账户实测对照

核查日期：2026-10-22。标注规则：`文档` 表示官方页面明确写出；`实测` 表示本轮真实调用观测；`未知` 表示两者都没有覆盖。实测结果只代表当前账户和当前网络，不代表所有账户。

## 1. 服务地址与凭据

| 项目 | 文档 | 实测 | 判定 |
|---|---|---|---|
| ASR 端点 | `POST https://api.xiaomimimo.com/v1/chat/completions` | Token Plan 域名 `https://token-plan-cn.xiaomimimo.com/v1/chat/completions` 同样可用 | 端点复用对话接口，不是 `/v1/audio/transcriptions` |
| TTS 端点 | 同上 | 同上 | 不是 `/v1/audio/speech` |
| 模型列表 | `GET /v1/models` | 200，返回 6 个模型：mimo-v2.5-asr、mimo-v2.5-tts、mimo-v2.5-tts-voiceclone、mimo-v2.5-tts-voicedesign、mimo-v2.6-flash、mimo-v2.6-pro | 账户可见 ASR 与 TTS |
| 鉴权 | `api-key: $MIMO_API_KEY` 或 Bearer | 使用 `api-key` 头，全部成功 | 一致 |
| 凭据类型 | 文档区分按量计费 API Key 与 Token Plan 专属 Base URL 和 Key | 当前 `tp-` 前缀密钥在 `token-plan-cn` 可用；同一密钥打 `api.xiaomimimo.com` 返回 401 `invalid_key` | 密钥与 Base URL 必须成对配置 |
| 计费归属 | 按量计费页面写明普通 API Key 与 Token Plan 额度不互通 | 无法从响应判断本次调用记在哪个额度；控制台未查 | 未知 |

## 3. TTS

| 项目 | 文档 | 实测 | 判定 |
|---|---|---|---|
| 模型 | `mimo-v2.5-tts`（预置音色）、`-voiceclone`、`-voicedesign` | 只测 `mimo-v2.5-tts` | 另两个未验证 |
| 文本位置 | 待合成文本放在 `role: assistant` 的 `content`，不能放 user | 一致 | 一致 |
| 输出格式 | `audio.format` 取 `wav`/`mp3`/`pcm`/`pcm16`，默认 wav；`stream:true` 时默认 pcm | wav、pcm16、mp3 均返回 200；stream 与非 stream 均可 | 一致 |
| 采样率 | 流式示例按 24000 Hz 写文件 | WAV 头为 24000 Hz，PCM 长度按 24 kHz 单声道 16 位折算吻合 | 24 kHz |
| 声道与位宽 | 示例注释为 PCM16LE mono | WAV 为 1 声道 16 位；PCM 长度均为偶数且按单声道解释合理 | 单声道 16 位 |
| 音色 | 预置列表含 mimo_default、冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean；中国集群 `mimo_default` 映射冰糖 | 冰糖与 mimo_default 均成功，输出长度不同 | 一致 |

| 文本长度上限 | 文档未写 | 47 字符合成成功，未触边界 | 未知 |
| 流式分片 | 文档建议流式时用 pcm16 拼接 | 23 个 chunk，拼接后 307200 字节，可解码 | 一致 |

## 4. 限制与配额

| 项目 | 文档 | 实测 | 判定 |
|---|---|---|---|
| ASR 限流 | 100 RPM，10K TPM | 未触发 | 未验证 |
| TTS 限流 | 100 RPM，10M TPM | 未触发 | 未验证 |
| 并发 | 每账号有模型并发上限，高负载可能返回 429 | 串行调用，未触发 | 未验证 |
| 重试建议 | 指数退避 | 本轮不重试，失败样本原样记录 | 设计输入 |

ASR 的 10K TPM 比 RPM 更紧：15 秒音频实测 `prompt_tokens=116`，按此估算每分钟约 86 次请求就会先撞 TPM。产品是单用户按键触发，不构成限制，但批量测试时要注意。

## 5. 计费

| 项目 | 文档 | 实测 |
|---|---|---|
| ASR | 国内每输入音频小时 0.5 元，时长精确到秒 | 响应 `usage.seconds` 与实际时长不一致，见下 |
| TTS | 三个 TTS 模型限时免费 | 未查账单 |
| 计费秒数 | 文档只说精确到秒 | 1.000 秒记 2 秒，3.000 秒记 4 秒，5.000 秒记 6 秒，15.000 秒记 16 秒，6.080 秒记 7 秒，即向下取整后加 1 秒 |

计费秒数比实际时长多约 1 秒，按 15 秒上限估算每次调用按 16 秒计，误差约 6.7%。这不是产品缺陷，但预算与成本估算要按 16 秒算。

## 6. 错误码

| 状态 | 文档含义 | 本轮实测 |
|---|---|---|
| 400 | 请求体格式错误、模型不存在等 | 传不存在的 TTS 模型返回 400，正文为 `{"error":{"code":"400","message":"Unsupported model ..."}}` |
| 401 | 缺少或无效密钥；混用 Token Plan 与按量付费密钥 | Token Plan 密钥打按量计费域名返回 401 `invalid_key` |
| 402 | 余额不足 | 未触发 |
| 403 | 地区限制或风控 | 未触发 |
| 404 | 接口或模型不支持 | 未触发 |
| 421 | 内容拦截 | 未触发 |
| 429 | 请求超限或 Token Plan 额度耗尽 | 未触发 |
| 500 / 503 | 服务端故障或过载 | 未触发 |

401 的两种原因（密钥无效、密钥与 Base URL 不匹配）在响应正文上无法区分，板端只能把两者合并成配置错误处理，并在本地日志记录 Base URL 主机名。

## 7. 数据保留与使用

| 问题 | 官方表述 | 判定 |
|---|---|---|
| 是否收集音频 | 隐私政策写明为提供 API 服务需要收集文本、图片、视频、音频信息 | 明确收集 |
| 是否用于训练 | 隐私政策写明未经事先同意，不会将提供的文本内容用于模型训练或其他用途 | 文本明确；音频未被这句话覆盖 |
| 保留多久 | 隐私政策写明按收集目的必需期间或法律要求保留，目的完成后删除或匿名化 | 无固定天数，不可承诺 |
| 存储位置 | 隐私政策写明境内服务的信息保存在中华人民共和国境内 | 明确 |
| 删除方式 | 隐私政策提供通过 privacy.mi.com/support 申请访问、更正、删除 | 有渠道，无 API |
| 音频响应有效期 | TTS 响应 `audio.expires_at` 字段当前恒为 null | 无到期时间，实际由谁清理未知 |

结论：板端本地释放录音不能替代云端删除承诺。产品文案不能写云端不保留，只能写本机不保留。
