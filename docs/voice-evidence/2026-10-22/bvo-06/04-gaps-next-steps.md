## 2. 阻塞与风险

### 2.1 凭据与计费

当前使用的是 Token Plan 的 `tp-` 密钥，只能配 `token-plan-cn.xiaomimimo.com`。实测同一密钥打按量计费域名返回 401。两个风险：

1. Token Plan 额度耗尽时 ASR/TTS 会返回 429，与密钥错误、模型不支持的表现不同，板端需要分开提示。
2. ASR 在按量计费页面标价每小时 0.5 元，TTS 限时免费。本轮无法确认这些调用记在哪个额度上，演示前要在控制台核对一次余额与用量。

本轮没有注册新账号、没有充值、没有修改付费配置。

### 2.2 板端内存

15 秒单声道上传需要约 640 KB 的 base64 字符串，现有 `llm_proxy` 还会再生成一份等长的 JSON 字符串。开机空闲堆约 837 KB，整包方式不可行。这不是接口限制，是传输实现限制，属于 BVO-07。

### 2.3 采样率不一致

TTS 返回 24 kHz，板端播放链路是 16 kHz。转换本身不难，但重采样会引入延迟与音质变化，需要在 BVO-11 听音确认。另一条路是把播放采样率改到 24 kHz，未验证。

### 2.4 数据保留

云端是否保留录音、保留多久、是否用于训练，官方只给出原则性表述，没有固定期限，也没有删除 API。产品不能对外承诺云端不保留。

## 4. 演示前的检查清单

1. 控制台确认密钥类型、Base URL 与额度，三者一致。
2. 板端配置的 `MIMO_BASE` 与密钥成对，切换域名必须同时换密钥。
3. 至少用一段真实用户普通话跑一次 ASR，记录识别结果与耗时。
4. 至少听一次 TTS 播报，确认数字、UPS、点位 ID 的读法。
5. 断网、DNS 失败、429 三种故障各跑一次，确认 30 秒内有明确失败提示。
