# 语音三意图、事实隔离与生命周期续接

日期：2026-10-23。接续 BVO-07/08/10/13/14；阶段 A/B 仍未通过。本目录区分诊断试跑与固定测试集，保留修复前失败，不把合成语音作为真人麦克风或听音验收。

## 当前变更

- 回答按 C 已解析的意图和点位再次执行对应只读工具。发布快照时仅捕获当前线程的数据，显示和播报使用同一份私有副本；其他线程、后台工具或旧请求发布的新全局序号均不能替换它。模型文本不作为事实回答。
- 语音 SDK 请求只声明并允许 vg_point_read、vg_anomaly_read、vg_alarm_recovery。C 层在执行任一单独或并行工具前检查所有名称，并跳过可能执行文件/命令的自然语言和斜杠捷径。后台保留原权限。
- 受控语音选择已配置模型时只更新内存，不把五个配置字段在每轮重写到 eMMC。旧显式配置/后台接口保持原行为。ai_agent 代码提交 `49aaea3`。
- 点值语音在单次工具调用后直接交给 C 事实校验，不因诊断问题措辞再请求一次模型。异常和恢复继续使用单次工具结果捷径。
- 语音点位解析接受 ASR 的句末问号/句号，优先精确 ID/名称，拒绝唯一部分名称直接选点；未知点位保留其 token，只有明确代词追问能复用最近点位，恢复追问保持恢复意图。
- 正常/异常回答不再把异常数当作已确认点数。结束与两分钟空闲清理已收起的 UI 数据；播放等待轮询取消，产品播报 WAV 在设备空闲后清理。
- 新增诊断 counters 与 text_ready/first_playable 单调耗时，供确认静音跳过 TTS 和 30 秒预算；这些指标不加入产品 UI。

## 主机与来源

`host-tests-*.log` 为实际回归；首次新增 scope 测试漏链接 libm，`host-tests.log` 保留链接失败，修正后各版通过。快照并发测试包括另线程发布旧数据、失败工具无发布、退出后副本不可变和三个意图。`facts-asan.log` 为 AddressSanitizer/UndefinedBehaviorSanitizer 通过。scope 测试使用仓库平铺工具格式并调用实际 OpenAI 工具转换器，检查最终请求仍有三个声明；runtime-config 测试断言受控选择产生零次配置写入、旧接口仍持久化。

`firmware*.json` 保存每次真实烧录的多仓 HEAD、dirty 源文件、配置和镜像/ELF 摘要，`flash*.log` 对应烧录。首轮固定样本使用 `firmware-shortcut.json`。

模拟从站使用 COM7、9600 8N1，只应答板端 FC03/04；板端保持唯一主站。正常模式对应 14 点在线、ups_load=40 %、温度=24。本轮不编辑或应用点表，不操作寄存器写入。

## 已保留的试跑失败

`three-intents.log`：异常问句在约 23 秒仍查询中，随后人工脚本主动结束，核心 rc=-7/tools=0，问题和回答清空；这不是 30 秒超时样本。点值/恢复的 ASR 返回 UPS负载是多少？、UPS负载恢复了吗？，旧解析器因问号拒绝匹配，修复前两个问句均失败。

`scoped-pilot.log`：修正问号后，点值能查到 ups_load=40 %，但旧问题措辞未命中通用点查捷径，额外模型调用使 TTS 超时；已增加语音专用工具结果捷径。异常文本错误输出共 0 个已确认点位，已修正；该轮 TTS 返回 200 后预算不足，按播报失败保留文字，不能计完整成功。

首次临时样本服务在预装文件时到达 600 秒上限，部分 wget 留下空文件，因此 pilot 恢复样本 ASR 返回 io/req=0。它是测试准备失败，未当作服务或模型故障，也未从记录中删除。重启有界样本服务后重新预装，并按样本字节数核对再做固定测试集。

## 固定样本与验收范围

`cases.json` 是预先固定的 30 个不同中文问句，三类各 10 条；`sample-manifest.json` 记录本机 SAPI Huihui 合成 WAV 的格式、时长、字节数及 SHA256。全部是合成文本，没有个人录音。`make_samples.ps1` 可复现生成；`serve_samples.py` 仅服务这些命名 WAV、限制时间/请求数，不服务目录或凭证。源 WAV 留在本机临时目录，不纳入产品交付。

固定测试集运行结果另补原始记录与统计，未运行完不得按 27/30 目标记成功。所有诊断、准备失败与正式测试分别登记。

## 固定 30 条首轮结果

固件为 `firmware-shortcut.json`，原始记录为 `matrix-anomaly.log`、`matrix-point.log`、`matrix-recovery.log`。30 个输入先逐一与主机 WAV 字节数比对，见 `preload-check.log`。统计由 `check_matrix.py` 生成，全部尝试见 JSON/CSV；未删除超时或失败。

| 类别 | 完整程序链路 / 尝试 | 得到正确文字 | 成功样本首次可播放中位/最大 |
|---|---|---|---|
| 当前异常 | 8/10 | 10/10 | 29020/29980 ms |
| 点值 | 0/10 | 7/10 | 无成功样本 |
| 恢复 | 0/10 | 9/10 | 无成功样本 |
| 合计 | 8/30 | 26/30 | 目标 27/30 未达到 |

完整程序链路指有已校验文字、TTS 完成、可播放文件提交并进入结果态；不代表已人工听音。首次可播放耗时由板端单调时钟记录，后续音频时长不计入该指标。成功样本耗时单列的同时保留 22 次失败，不能只看成功样本宣称性能通过。

点值的 7 次文字均为 ups_load=40 %；恢复回答在没有事件证据时明确无法确认，没有把当前正常当成已恢复。另有两次 ASR 网络发送失败与一次点值模型超时；其他主要失败是 TTS 预算耗尽。采集过程中 14 点保持在线，运行统计无 CRC/超时/其他帧错误；语音负载下平均响应延迟增加，原始数值保留在各批前后 dump。线程栈最高约 29448/49128 B。堆和 TCP 状态按每批记录，不能据此宣称长期稳定。
