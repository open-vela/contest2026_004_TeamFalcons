# 10: 故障注入、长测与发布证据

**What to build:** 形成 OTA 的失败恢复和发布验收证据。覆盖下载写盘、临时文件改名、pending BCB 写入、QSPI 擦除、QSPI 页编程、B 槽 trial 启动和 confirmed 写入的断电点；覆盖 FAT、BCB、manifest 和镜像损坏，trial 超限，存储写失败，下载中断和重复安装。生产构建必须排除测试 fixture、测试公钥、测试 CA 和测试凭据。长测确认没有启动循环、空间泄漏或状态机卡死。

**Blocked by:** 09、05。

**Status:** ready-for-agent

- [ ] 断电点矩阵按 A/B 策略恢复，设备不会跳转到无效地址或进入启动循环。
- [ ] FAT、BCB、manifest、镜像损坏，trial 超限，存储写失败和下载中断都能回到 A 或安全终止。
- [ ] 重复下载、安装、回滚和失败重试后，eMMC 空间、日志和 MQTT 状态没有持续增长或卡死。
- [ ] 生产构建检查证明测试 fixture、测试公钥、测试 CA 和测试凭据不存在或不可用，未签名 manifest 被拒绝。
- [ ] 板级验收记录命令、串口输出和结果，不包含凭据、完整 URL 或私钥。
- [ ] 未执行的断电点或环境项明确标为未验证，不用主机测试代替设备证据。
- [ ] 遗留缺陷记录在案；P5 验收完成前不宣称 OTA 已完成。
