# 09: 断线、重放与容量压力下保持配置一致

**What to build:** 通信、界面和持久化联通后，板端在断网、重连、重复消息、队列耗尽和资源峰值下继续遵守会话与版本规则；云端只能依据真实板端结果判断配置状态。

**Blocked by:** 06, 重启后核对提交结果; 07, 通过专用 MQTTS 操作配置会话; 08, 板端查看依据并人工确认添加.

**Status:** complete

- [x] 断线使未提交确认失效，重连只查询对账，不自动重放 open、put 或确认；提交中的连接变化不打断已开始的本地提交。
- [x] 相同请求重发、异内容冲突、缓存回收后重放及延迟消息均不能重复落盘、弹窗或提交。
- [x] 测量 TLS、MQTT 缓冲、候选解析、冻结目标、界面快照和线程栈的资源峰值，队列满和超预算时整批拒绝。
- [x] 实际能力与目标预算不符时同步协议、云端限制和设备快照，只报告已验证容量。

验证记录：

- 成功 open/put 的缓存结果只在本活动会话和原 state_seq 仍匹配时复用；断线、取消、新候选或状态推进后不会复活旧响应。
- 并发 remote open 只有实际创建 gate 的线程可以继续；同 owner 的第二个 open 返回 busy，不能释放胜者 token。修复后并发测试连续 500 次通过。
- 候选请求身份与摘要保存在活动会话中，32 项 request cache 被覆盖后仍能识别完全相同 put，并拒绝同 req_id 的异内容重放。
- 主机测试覆盖等待确认断线、旧 open 重放、旧 put 重放、缓存回收、异内容冲突、双消息突发和超长消息。
- 真机重复 put 后 `awaiting_local_confirm`、state_seq 和 confirmation_id 均不变，没有重复确认窗口或落盘。
- 真机 TLS 在线且候选等待确认时，配置线程栈为 22720/32744 字节，占 69.3%；Usermem 可用 5723520 字节。
- 对象测量、队列策略和完整数据见 [config-mqtt-hardening.log](../../../maintenance-evidence/2026-11-05/config-mqtt-hardening.log)。
