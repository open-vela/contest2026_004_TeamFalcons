# VelaGuard 公式解析器完善计划

日期：2026-10-28。

状态：F1/F2 共用核心已在主机实现并通过测试；尚未接入 GUI、采集、点表、NSH/MQTT，未编译或烧录板端固件。后续阶段由用户选择启动。

## 1. 目标与范围

将 GUI 原型中的公式能力整理成确定性、可离线运行的共用 C 模块，供点表校验、真机采集和 GUI 预览调用。目标包含整数比例/偏移、多寄存器算术，以及显式字序的 IEEE 754 float32 解码。

先编译公式并检查结构与预算，在正常采集得到有效寄存器块后执行计算。公式只计算数值，不打开总线、不访问文件/网络、不修改配置、不清除告警、不控制输出，也不替代人工确认。

本文是对 [网页接入计划](velaguard-web-sensor-onboarding-plan.md) 的后续公式专项规划。现有 [MQTT 候选协议 v0.3](velaguard-candidate-mqtt-protocol.md) 仍只接受 int16/uint16、零偏移和单寄存器；本文不立即放开其字段或上报新能力。

## 3. 推荐的公式用法

新语言中的 R0..R3 表示当前测点读取范围内、按地址递增排列的原始无符号 16 位寄存器。R0 是 reg，R1 是 reg+1；它们不是全局寄存器地址，也不是其他传感器的值。

| 需求 | 表达式例子 |
|---|---|
| 无符号整数除以 10 | `R0/10` |
| 无符号整数比例与偏移 | `R0*0.1+2` |
| 有符号 16 位数值换算 | `S16(R0)*0.1` |
| 两个值做算术组合 | `(R0-R1)/10` |
| 两寄存器浮点，ABCD 顺序 | `F32_ABCD(R0,R1)` |
| 浮点解码后换算 | `F32_ABCD(R0,R1)*0.1+2` |
| 两寄存器浮点，交换字顺序 | `F32_CDAB(R0,R1)` |

R0 单独转为浮点数参与运算时，0..65535 可精确表达。S16 明确执行有符号解释；不能将 0xFFFF 直接作为普通 R0 期望得到 -1。

四则运算按 float32 工程值语义执行，不承诺对大整数保持完整整数精度。`R0*65536+R1` 是数值运算，不能替代 IEEE 754 位模式解码。首版不扩展 uint32/int32/float64 精确值通道。

## 4. 语言与字序

### 4.1 首版语言

- 数字：十进制整数、小数及十进制科学计数法；小数点固定为点号。拒绝 NaN、Inf、十六进制浮点字面量和越界常量。
- 变量：仅 R0、R1、R2、R3，必须在该点 qty 范围内；至少引用一个输入寄存器。
- 运算：一元正负号、加减乘除、括号，采用通常优先级，不改变结合顺序。
- 函数：仅 S16 和 F32_ABCD/F32_BADC/F32_CDAB/F32_DCBA。
- 解码函数参数只能是寄存器变量。F32 的两个参数必须是按地址递增的相邻寄存器；由函数名决定排列，不用调换参数顺序隐含字序。
- 标识大小写不敏感，保存并确认原公式字节，不通过重排或改写公式改变摘要口径。
- 表达式只接受 ASCII，允许空格和制表符，不允许换行、NUL、分号、赋值、循环、用户函数、字符串或脚本执行。
- 不增加跨传感器引用、历史值引用、条件语句、位运算或任意数学函数。后续需要时先增加语言版本及对应预算。

语法示意：

```text
expr     := product { ("+" | "-") product }
product  := unary { ("*" | "/") unary }
unary    := ("+" | "-") unary | primary
primary  := number | register | "(" expr ")" | signed16 | float32
register := R0 | R1 | R2 | R3
signed16 := S16 "(" register ")"
float32  := F32_order "(" register "," register ")"
order    := ABCD | BADC | CDAB | DCBA
```

一元运算与括号共享深度预算，不能通过反复一元负号绕过嵌套上限。数字词法先由模块检查，再做有界转换；不把 libc 数字转换函数支持的全部输入都开放为公式语言。

### 4.2 浮点解码定义

A、B、C、D 表示目标 IEEE 754 float32 位模式从高到低的四个字节；函数后缀表示这些字节在两个输入寄存器中的顺序。寄存器是 Modbus 库返回的数值，不依据主机内存里的 uint16_t 字节排列解释。

| 函数 | 输入 R0、R1 | 预期结果 |
|---|---|---|
| F32_ABCD | 0x41CC、0x0000 | 25.5 |
| F32_BADC | 0xCC41、0x0000 | 25.5 |
| F32_CDAB | 0x0000、0x41CC | 25.5 |
| F32_DCBA | 0x0000、0xCC41 | 25.5 |

按无符号位宽组装 32 位模式，再使用明确的位复制方式得到 float；不使用浮点数值强转来代替位重解释，不通过不匹配指针解引用。编译时核实 CHAR_BIT、整数宽度与 float 的 binary32 表示条件，不满足时不启用 F32 能力。

排列语义参照 libmodbus 的官方 [ABCD](https://libmodbus.org/reference/modbus_get_float_abcd/)、[BADC](https://libmodbus.org/reference/modbus_get_float_badc/)、[CDAB](https://libmodbus.org/reference/modbus_get_float_cdab/)、[DCBA](https://libmodbus.org/reference/modbus_get_float_dcba/) 文档；本项目保持现有 Modbus 承载，公式模块不新增 libmodbus 依赖。

## 5. 共用模块与接口

建议新增本仓 `app/velaguard/vg_formula.c`、`vg_formula.h`，源码不依赖 LVGL、NSH、JSON、网络或设备 I/O。GUI 和板端调用同一实现，测试也通过同一接口覆盖行为。

推荐接口形状，以下只表示设计，不是已存在声明：

```c
struct vg_formula_spec
{
  unsigned int version;
  unsigned int reg_count;
  const char *expr;
  size_t expr_len;
};

int vg_formula_compile(const struct vg_formula_spec *spec,
                       struct vg_formula_program *out,
                       struct vg_formula_error *error);

int vg_formula_eval(const struct vg_formula_program *program,
                    const uint16_t *regs, size_t reg_count,
                    float *value, struct vg_formula_error *error);
```

接口约束：

- compile 检查语言版本、显式长度、词法、语法、变量、函数、参数数量和资源上限，生成有界中间指令及寄存器引用集合。
- program 使用调用者分配的固定容量内存，不保留指向临时表达式的悬空指针；成功后只读。失败的输出不得当作有效 program 使用。
- eval 使用固定栈执行已验证指令，不在每轮采集中重新解析字符串，不动态分配内存，不递归执行表达式。
- 输入寄存器数量必须匹配编译时声明。读取成功、完整性、时间戳和配置代次由采集调用者检查；eval 不自行读取缺少的寄存器。
- 失败返回稳定错误码与从 0 开始的源字节位置，value 不写入伪造的零值。没有源位置的输入错误使用明确的无位置标记。
- 模块无可变全局求值状态，可由 GUI 校验和采集分别使用。相同 program 在不同调用者中使用各自执行栈。
- 只持久化语言版本与公式原文，不把与编译器/架构相关的指令布局写入点表或 MQTT。

配置被接受时编译一次；启动加载已确认表时重新编译。编译结果与点表代次绑定，换表后旧采样和旧执行结果不得发布到新点表。

## 6. 校验、数值与执行预算

### 6.1 静态校验与运行错误分开

`1/(R0-1)` 在语法和引用合法时可以编译；只有实际 R0=1 时返回除零错误。不能因为对模拟值 1 试算失败，就把整条公式判成语法错误。

可静态证明的非法内容直接拒绝，例如未知函数、缺括号、超范围寄存器、错误函数参数和固定除零。其他数据相关问题在每次执行中判断：

- 分母为 +0 或 -0 时返回 division_by_zero；有限且非零的小分母按正常计算，不使用固定 epsilon 代替零判断。
- 每步运算及 F32 解码检查结果有限性；NaN、Infinity、溢出不能进入有效测量值或告警比较。
- 常量解析检查结束位置与范围错误。非零常量或非零计算结果下溢后不能静默当作零。
- F32 解码通过位复制组装 32 位模式，不经过浮点运算，因此解出的次正规数位模式在主机和板端都保真。乘除结果为零且两个操作数都非零时返回 underflow，覆盖目标 FPU 刷新为零的行为；该判定在 F2/F5 仍需用真实板端复核。
- 允许真实正负零；显示遵循现有数值格式，作为分母时均视为零。
- 采用明确的 float32 运算顺序，编译阶段不重排表达式。不得对该模块启用会破坏 NaN/Inf 检查或改变此语义的优化选项。

固定常量公式不能绕过采集有效性。即使某表达式在数学上可能得到常数，也必须先取得该点要求的完整有效采样，再执行。

### 6.2 建议初始预算

| 项目 | 建议上限 |
|---|---|
| 公式原文 | 127 ASCII 字节，另留 NUL 位置；GUI 当前 63 字节不是新上限已经实现 |
| 原始寄存器 | 每点 1..4 个，同一连续读取块 |
| 编译后指令 | 每点最多 64 条 |
| 运算栈 | 最多 16 个数值 |
| 编译嵌套 | 括号与一元运算合计最多 8 层 |
| 测点 | 沿用整表最多 32 点 |
| 候选传输 | 仍计入完整 MQTT 消息预算，不为公式自动放宽包长 |

编译时计算最大栈深和指令数；执行时仍检查 program 元数据与输入数量，不相信传入内存一定有效。预算不受模型请求或公式字段覆盖。

若每条指令按 8 字节估算，64 条约 512 字节/点，32 点约 16 KiB；活动与候选同时缓存约 32 KiB，尚未包含原文、栈和元数据。这只是估算，须测 sizeof、堆峰值、线程栈与完整周期耗时，避免把大数组反复复制进现有多个点表快照。

初始资源预检不通过时停止集成、重新收紧预算；不能用静默截断公式、栈或指令解决。运算不放在 LVGL 绘制回调或 MQTT 收包回调中执行。

## 7. 采集链路接入

建议数据流程：

```mermaid
flowchart LR
    C[已确认配置与编译结果] --> P[正常 Modbus 连续读取]
    P --> S[完整寄存器块和采集状态]
    S --> E[共用公式执行模块]
    E --> V[工程值与数据质量]
    V --> U[屏幕、快照、告警和 MQTT]
```

- 新采集结果返回每点 words[4]、实际数量、传输状态和采集代次；不再只保留首个寄存器。调用者按点表 reg/qty 发出一个完整读取请求。
- 一个公式只能使用同一从机、功能码、地址块和采集请求返回的数据，禁止拼接不同轮次或旧缓存。完整同帧返回不证明从机内部更新原子性，仍需手册依据；本任务不增加锁存寄存器写入。
- FC03/FC04、固定 9600、地址范围及 reg+qty 的边界检查保留。公式执行不会触发额外扫描或隐藏总线访问。
- 原 int16/uint16 点有效读取数仍为 1，兼容其现有 scalar 行为；新公式点才按已验证 qty 读取完整块。
- 输入未完整返回或点表代次变化时不执行/发布。求值前后核对 program、点位和采集快照属于同一配置代次。
- 分开记录传输成功与工程值有效性。公式除零不能计作 Modbus CRC、超时或总线离线；也不能发布新鲜的 ok=true/零值。
- 求值失败时，UI 可以保留带原时间的最后有效值并明确无效，或显示不可用；AI、日志和 MQTT 不得把旧值当作本轮成功数据。
- 无效新值不能触发告警恢复或清除已有告警；采集、数据质量与告警状态的传递需覆盖真实回归用例。现有离线规则保持其传输失败口径。
- 如需给快照/MQTT 增加质量原因字段，先完成相应兼容设计；不改变既有主题，也不以模型解释替代确定性错误原因。

## 8. 点表、旧配置与回退

### 8.1 新旧计算路径只有一个结果来源

旧 schema 1 的 int16/uint16＋scale 在内存中按等效语义接入：

- uint16：`R0 * 原 scale`。
- int16：`S16(R0) * 原 scale`。

倍率以原有实际浮点精度传入，不能经低精度字符串格式化改变数值；旧的零倍率、负倍率及边界值按现有合法性规则兼容。旧点的运行字段和阈值不因添加公式点而被重置。

GUI 旧类型模板也须结合原数据格式做显式适配：旧模板中的 R0 可能按有符号解码值使用，不能只复制文本后改成无符号寄存器语义。原型中的 float32 和字序选项不作为已验证配置自动导入；适配与错误拒绝需要独立用例。

推荐后续运行表 schema 2 支持旧点与公式点并存。公式点必须有 `dtype=formula_v1`，用 formula.version 和 formula.expr 描述唯一计算路径，不同时接受 scale、offset 或另一个字序字段再次换算。原文中的类型、倍率和字序保留在来源信息中供核对。

下面仅是未来运行文件中的点记录形状示例，不是现行 NSH/MQTT 可接受输入：

```json
{
  "id": "s1_f3_r0",
  "name": "温度",
  "addr": 1,
  "fc": 3,
  "reg": 0,
  "qty": 2,
  "dtype": "formula_v1",
  "formula": {
    "version": 1,
    "expr": "F32_ABCD(R0,R1)"
  },
  "unit": "C"
}
```

### 8.2 不能只依赖根版本号

当前旧读取器未校验 schema_version，不能假定它会拒绝 schema 2。新格式中公式点的必需 dtype=formula_v1 可使现有只接受 int16/uint16 的校验器整表拒绝，防止忽略公式后按默认 int16 采集；必须用实际旧读取器做回归验证，不凭文档推断通过。

新读取器需要严格校验根版本、每点分支、字段白名单与语言版本；缺类型、混用公式与倍率、未知函数或编译失败整表/整候选拒绝，不默认降级。

旧固件拒绝新表不等于能够继续监测全部点位。回刷旧固件前须经人工维护恢复已验证的 schema 1 备份；含公式点的新表不能无损自动降级。保留原表、来源和提交记录，验收失败时恢复明确的旧配置，不把损坏/不兼容表当空表或镜像默认表。

现有 NSH、周期采集、首页、告警和 MQTT 必须通过统一点表转换与提交逻辑。不能只让新入口识别公式，而旧入口忽略它、丢字段或覆盖来源。原 NSH 命令表的扩展在专门协议任务中定义；120 字节命令限制不能通过拆成未确认的 shell 片段绕过。

## 9. 候选下发与权限

现有候选协议 v0.3 保持不变。未来公式扩展需要明确的新协议/候选版本与能力集合，至少报告公式语言版本、支持函数、最大公式字节、寄存器数和指令预算。旧协议严格拒绝新增字段，不能仅增加一个字符串就宣称兼容。

建议新候选 profile 使用 candidate_schema_version=2；外层消息与能力形状有不兼容修改时同步增加 schema_version。云端先通过受支持的只读版本查询确认能力，不能用超时或旧 retained 状态推测支持公式。

- 云端模型可生成带原文依据的候选公式；网页仍只做预览与测点选择，不开放任意表达式编辑。
- 板端独立编译并校验函数、寄存器范围及预算。云端校验通过不能替代板端校验。
- 原文公式、读取范围和语言版本参与候选摘要及人工确认展示。任何修改产生新候选版本并使旧确认失效。
- 新远程入口保持不试读；编译校验完全离线，不发送新增候选的 Modbus 请求。板端人工确认后才进入正常读取。
- NSH 继续遵守其人工确认流程；设备端 Agent 不得生成已生效配置、执行公式配置命令或代确认。
- 不恢复屏幕自由配置、旧 MQTT AI Bridge、远程 apply/confirm 或寄存器写入。

每阶段形成可检查结果，后续由用户选择启动；本计划没有自动授权全部开发。

| 阶段 | 交付 | 验收条件 |
