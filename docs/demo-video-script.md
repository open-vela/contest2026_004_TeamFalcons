# VelaGuard 演示视频脚本

> 作品提交必交物。时长上限 5 分钟，本稿按 4 分 30 秒设计。
> 目标机器：STM32H750B-DK + openvela，主线固件 `velaguard-lvgl`。
> 拍摄前必须过完第 0 节的三个门槛，未过的拍号按第 0.3 节降级处理。

## 0. 拍摄前置门槛

第 5、6、7 拍依赖板端 Agent 真正跑通一轮。开拍前逐条验，任一不过就走降级方案。

| 门槛 | 判据 | 影响的拍 |
|---|---|---|
| G1 Agent 能调工具 | 注入一条告警后，串口出现 `[vgadvice] asked for N alarms` 与至少一次 `Executing tool:`，并在 `/data/velaguard/reports/alarm_advice.txt` 里看到产物 | 5 |
| G2 工具层会拒绝 | 让 Agent 改点表时出现被拦截的记录 | 6 |
| G3 报告为 Agent 产出 | 报告页标题显示「AI 日报 · OPENVELACLAW」，来源行写明经只读工具生成 | 7 |

### 0.1 已知阻塞

2026-09-16 上午的板端记录里，LLM 回环是断的（`Write request failed: -3`、`net_connect ... ret=0x42`）。当天已定位并修掉两个真实缺陷，傍晚的复测通过：

```text
[llm] OpenAI API with tools (model: mimo-v2.5, ...)
[tools] Executing tool: read_file
[tools] Executing tool: run_shell
[trace:...] END status=ok iters=6 tools=5 llm_ms=105010
```

- `vela_tls.c` 把 socket 固定成阻塞模式，mbedTLS 的 `net_would_block()` 因此在缓冲满时不返回 WOULD BLOCK，约 16 KB 的 LLM 请求体必然写失败。改为分块写加有界退避重试（公共树分支 `velaguard/llm-tls-send-retry`）。
- `agent_loop.c` 的同名工具重复保护会在第 5 次 `run_shell` 时直接结束循环，既没有结束语也没到迭代上限，整轮判失败。改为按迭代上限同样方式收尾。

证据：`.trellis/tasks/09-16-ai-contract-request-channel/research/gate0-ask-20260916-r3.txt`。

开拍前仍要现验一遍：`config_show` 的 LLM Host、Path 与 Model 是否与实际服务一致，`vgprovision status` 是否有效，token 是否过期。

### 0.2 降级方案

G1 不过时，第 5 拍改用已有上板记录素材（串口日志、历史录屏），画面角标只写录制日期与当时条件，不做说明性文字。G2 不过时，第 6 拍整拍删除，时间补给第 4 拍。G3 不过时，第 7 拍改为串口 `cat` 报告文件，机位不变。

降级后全片时长会缩短，按第 5 节的比例回填到第 4、5 拍的画面停留，不要拉长旁白凑时间。

### 0.3 全片定位句

**它能在没人看着的时候自己发现故障、自己说明白，但动不了设备。**

主动在前，边界在后。所有画面都为这两句服务。

## 2. 逐拍脚本

### 第 1 拍 现场与定位（0:00–0:18，字幕 40 到 55 字）

**画面**：俯拍桌面。必须同框出现板子、扩展板、RS485 接线和网线。屏幕亮着，首页数值在跳动。镜头缓慢推近屏幕。

**动作**：无。镜头停住三秒再走。

**旁白**：

> 现场有一根陌生的 485 总线，没人守在柜子旁边。VelaGuard 是一台独立运行的 RS485 网关，它要自己看懂这根线，出事时自己说明白。

**不要**：念功能清单。不要出现产品没做的事。

---

### 第 2 拍 认总线与确认闸门（0:18–1:03，字幕 100 到 120 字）

**画面**：主画面切板子屏幕的总线探查页；串口终端做画中画，字号调大。

**动作**：

1. 手指点开「启用总线扫描」开关。给开关一个近景，说明它默认是关的。
2. 点「开始扫描」→ 进度文字滚动 `扫描中 n/32 · 9600 · FC03@reg0/1/2`。
3. 扫描完成，出现 `扫描完成 32/32 · 请确认写入`。
4. 点试读，串口出现实际读数值。
5. **停住**。手指离开屏幕，给三秒空镜。
6. 点确认写入。首页出现点位，数值开始跳。

**旁白**：

> 接入第一步是认总线。屏上打开扫描开关，开关默认关着，要人手开。网关按 9600 波特率扫地址 1 到 32，探测每个从站的寄存器块，生成候选点表。
> 候选表不会自动生效。先试读一次，把真实值读出来给人看，人确认之后才写入。这道闸门是刻意留的——现场误判一张表，后面所有数据都不可信。

**要点**：第 5 步的三秒空镜是这拍的重点，不要剪掉。旁白要落在「人确认之后才写入」上，不要落在扫描速度上。

---

### 第 3 拍 变成独立设备（1:03–1:15，字幕 20 到 30 字）

**画面**：主机位，手入镜。

**动作**：当着镜头拔掉 ST-LINK USB 线。镜头立刻回屏幕，数值仍在跳动。

**旁白**：

> 配置完就拔掉调试线。从这一刻起，它是一台独立设备。

**要点**：拔线动作必须清楚入镜，这是与纯云端方案的分界线。拔完不要立刻切走，留两秒看数值继续跳。

---

### 第 4 拍 本地安全环（1:15–2:15，字幕 110 到 135 字）

**画面**：主机位对准屏幕，串口终端画中画。

**动作**：

1. 把水浸从站寄存器置 1。屏幕告警页弹出，红色严重级，显示当前值与阈值。
2. 串口 `ls /data/velaguard/pending_alarm.txt`，再 `cat` 一次，露出文件内容。
3. 告警页点一次「静音」，再点一次「标记处理」，各停两秒。
4. 复位水浸为 0。
5. 拔掉该从站的 485 线。滑窗判定后告警页出现离线条目。
6. 插回 485。数值恢复，告警解除，页面回到无活动告警。

**旁白**：

> 往总线上注入一次水浸。规则引擎在板上判定超阈值告警，屏幕立刻弹出告警页，同时把这条告警落成一个待处理文件。
> 拔掉这根 485 线。窗口内连续失败到阈值，判定为离线。
> 插回去，数值恢复，告警自动解除。
> 这三段全部由确定性 C 代码完成，没有网络，也没有 AI 参与。

**要点**：全片最长的一拍，信息密度要撑住。三段递进按阈值、落盘、离线与恢复走，每段之间给半秒空镜。旁白最后一句要落在确定性上。

---

### 第 5 拍 Agent 解释告警（2:15–3:03，字幕 85 到 105 字）

**画面**：串口终端全屏，字号调到评委能看清 `Executing tool:` 的程度。

**动作**：

告警注入后板端会自己发起这一轮，不需要手工提问。等这一轮跑完（约三分钟），串口依次出现：

```text
[vgadvice] asked for N alarms
Executing tool: run_shell
Executing tool: run_shell
Executing tool: write_file
[vgadvice] advice loaded: N entries
```

随后输出中文解释。产物是 `alarm_advice.txt`，拍完在 NSH 里回读：

```text
nsh> cat /data/velaguard/reports/alarm_advice.txt
```

**不要**用手工 `ask` 冒充这一拍。手工 `ask` 发起的轮次 owner 是 manual，写出的文件与板端当前轮次的 `boot` / `req` 对不上，会被解析器整份拒绝，不会上屏，串口也没有 `[vgadvice]` 那几行，不能作为这一拍的上屏证据。这一拍要拍的是板端自己发起的那一轮。

**旁白**：

> 现在看 Agent。触发它的是刚才那条告警，不是我的提问。按 alarm_interpretation 这份自定义 Skill，它调 vgstats 拿通信质量，调 vgmodbus 读实时值，最后写出一份解释。
> 日志里每一行工具调用，都是只读命令。

**要点**：每条 `Executing tool:` 日志行停留不少于 1.5 秒，这是全片最需要评委看清的证据。旁白讲清三件事：为什么触发、按哪份 Skill、调了哪些工具。

---

### 第 6 拍 动手会被拦（3:03–3:29，字幕 55 到 75 字）

**画面**：串口终端全屏。镜头不要切走。

**动作**：

```text
vela> ask 把温度的严重阈值改成 50
```

期望：模型尝试调用点表写入命令，工具层返回拒绝，串口留下一行拦截记录，模型转述自己没有权限修改点表。

**旁白**：

> 现在让它改温度阈值。
> 它试了，工具层直接拒绝。这条边界写在 C 代码的工具注册里，不在提示词里。
> 全过程写操作次数是零。

**要点**：全片最有区分度的 30 秒。如果模型第一次直接拒绝而没有尝试调用，换一句更直接的问法，例如要求它执行 `vgpoint set`。拦截那一行必须在画面里停够两秒。

---

### 第 7 拍 运行日报（3:29–3:52，字幕 45 到 60 字）

**画面**：主机位对准屏幕，切到报告页；画面角落保留串口窗口，让 `Executing tool:` 几行可见。

**动作**：打开报告页，标题是「AI 日报 · OPENVELACLAW」，正文末尾一行写明「来源：板载 Agent（OPENVELACLAW），经只读工具生成」。镜头缓慢下移，让评委看完几行。

**旁白**：

> 第二个主动场景是运行日报。板端守护进程发现今天还没有日报，自己发起一轮，Agent 读 operations_report Skill，用 vgruntime、vgstats 这些只读工具取真实数字，再写回日报文件。这一段我没有提问。

**要点**：如果串口窗口来得及入镜，`Executing tool: get_current_time`、`run_shell`、`write_file` 三行就是这拍最硬的证据；拍不到也没有关系，报告页标题与来源行已经能区分 Agent 产出和固件的离线报告。最后那句是主动场景与问答的差别。

---

### 第 8 拍 断网降级（3:52–4:08，字幕 35 到 50 字）

**画面**：主机位。

**动作**：

1. 拔掉网线，动作入镜。
2. 再注入一次水浸告警。
3. 告警页照常弹出，行内的 AI 建议消失，详情头为「AI 建议不可用，显示规则摘要」，正文是确定性文本。

**旁白**：

> 拔掉网线，再注入一次告警。采集、告警、落盘照常。告警页回到本地规则摘要，它不会编一段解释出来。

**要点**：这一拍同时拿技术难度和诚信分。屏幕上的降级提示要拍清楚。

---

### 第 9 拍 回馈 openvela（4:08–4:30，字幕 45 到 60 字）

**画面**：README 滚动到公共仓 PR 表与板端 Skill 清单，最后定格在项目名一句话定位上。

**动作**：镜头跟随滚动，末尾定格三秒。

**旁白**：

> 底层改动都提了 PR 回 openvela 公共仓：QSPI 启动、以太网、显示加速、MQTT 移植层。VelaGuard：出事本地先叫，AI 讲人话，动手会被拦。

**待核**：README 的 PR 表当前列 8 个，技术报告写 9 个。开拍前定一个数字，两处与旁白保持一致。旁白若不确定，可说「底层改动都提了 PR 回 openvela 公共仓」，省略数量。

## 4. 后期剪辑说明

### 4.1 配乐

- 第 1 到第 3 拍用一条低音量铺底，节奏平稳，不抢旁白。
- 第 4 拍告警弹出处留一个短促的音效点，音量压到不盖住字幕。
- 第 5、6 拍降为近乎静音，让串口日志的滚动本身成为节奏。
- 第 8 拍拔网线处不加音效，留白。
- 第 9 拍回到开场那条主题，音量渐出收尾。
- 全片背景音乐整体压在负 24 dB 以下，旁白清晰度为第一优先。

### 4.2 转场

- 全片只用硬切与短叠化两种，不使用花哨转场。
- 第 3 拍拔线到第 4 拍告警页之间用硬切，强调因果。
- 第 5 拍进入串口全屏时用一次淡入，让评委的注意力切换。
- 拍与拍之间不留黑场。

### 4.3 画面处理

- 串口终端统一深色背景、等宽字体，字号以 1080p 下能看清 `Executing tool:` 为准。
- 屏幕画面做一次轻度裁切放大，去掉桌面杂物，保留板卡边缘作为真实感参照。
- 需要强调的日志行加一个细的描边高亮，不要用大面积色块。
- 降级素材（若使用）在画面右下角加日期角标。

### 4.4 剪辑硬规则

1. 不使用其他固件的画面冒充主线固件。
2. 不进入板上未实现页面的占位提示（诊断、OTA、趋势、日志、系统、添加传感器）。误入的画面必须剪掉。
3. 每个 `Executing tool:` 日志行停留不少于 1.5 秒。
4. 拦截记录那一行停留不少于 2 秒。
5. 第 3 拍拔线、第 8 拍拔网线两处动作必须完整入镜，不能只拍结果。
6. 片尾字幕：专属仓地址，并注明 AI Coding 日志已随仓提交。

## 5. 降级后的时长回填

若第 6 拍删除或第 5 拍改用记录素材，省下的时间按以下顺序回填，不要拖长旁白：

1. 第 4 拍各段之间各加 1 秒空镜。
2. 第 2 拍确认写入后的首页刷新多留 3 秒。
