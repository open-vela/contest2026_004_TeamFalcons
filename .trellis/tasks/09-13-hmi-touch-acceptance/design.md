# 触摸、导航与最终验收设计

## 1. 输入调度

- 在板端 `lv_nuttx_init()` 成功后，对有效 pointer indev 的 read timer 设为 10 ms，使用已有 `lv_indev_get_read_timer()`。
- 没有触摸设备时不解引用空指针；记录输入不可用，画面和本地采集继续，真机触摸项记失败/未测。
- 主循环对 `lv_timer_handler()` 返回的等待值做 `1..10 ms` 有界限制，再换算为微秒休眠。正确处理零值和 LVGL 无下一定时器的最大值，避免乘法溢出。
- 保留显示刷新 16 ms、系统 tick 10 ms、业务模型 1000 ms、原 FT5x06 中断模式、SWAPXY 和阈值 2。
- 所有输入和 UI 对象操作仍在 HMI 线程，不增加独立线程调用 LVGL。
- 实际休眠存在 tick 取整，必须从测量确认调度改善；不宣称配置 10 ms 就保证 10 ms 物理响应。

## 2. 按下、滚动和目标身份

使用 LVGL 原生 pointer/scroll 机制，主业务动作只处理有效 `CLICKED`。按下只显示视觉反馈，不触发确认、静音或扫描。

- 主要列表限定垂直滚动，保留原生惯性，关闭内容区弹性过冲，避免嵌套容器竞争同一手势。
- 用原生 scroll begin/end、press lost 和 release 管理状态，不另写基于事件次数的手势识别器。
- 按下时记录页面代次、点表代次、稳定点位 ID；告警操作额外记录该点告警期标识。
- 告警期标识为模型内部递增 epoch，在 `sensor_alarm_begin` 时变化，不写入点表或 Agent 协议。这样同一 ID 恢复后再次触发也不会接受上一次按下的确认。
- 点击释放前重新校验目标仍存在、告警期相同、页面/点表代次有效；失效则取消，不自动改作用到新下标或另一告警。
- 拖动已经开始、按下丢失或滑出目标，取消待点击。惯性滚动中的首次点按用于停止滚动，不能顺便处理告警。
- 切页时清理旧手势并等待当前触点释放后接受新页面点击，避免旧页面释放事件穿透。

## 3. 动态列表更新

稳定行对象和结构版本由子任务 2 提供，本任务加上手势期间的布局保护。

| 变化 | 手势期间 | 手势结束 |
|---|---|---|
| 数值、颜色、告警持续时间 | 原位更新，不改尺寸 | 无额外重建 |
| 成员增删、排序、筛选结构变化 | 保存最新待应用结构版本，保留当前视口几何 | 应用一次最新结构 |
| 被按下目标恢复/移除 | 立即取消其业务动作，必要时禁用；不把按钮重绑到邻行 | 移除或重排并恢复视口锚点 |
| 新高优先级告警 | 规则、计数和状态栏照常更新，不延迟判定 | 列表按既有优先级调整 |

视口锚点采用首个可见点位 ID 加像素偏移。目标消失时使用仍存在的相邻锚点并限制到合法滚动范围；不因每秒更新无条件回到顶部。

列表结构冻结只作用于正在操作的列表，结束或取消即解除。不能冻结模型、告警落盘或其他页面状态，也不能自动暂停采集。

## 4. 导航状态

继续使用既有 `vg_nav_goto/back`。将当前无所有权的 `args_copy` 替换为有界值类型导航记录，不引入堆分配的通用路由参数。

记录包含页面 ID、点表代次、选中点 ID、首页筛选、列表滚动位置、趋势 recent/all、选中告警 ID/期及报告版本对应的滚动位置。

- 导航深度维持 6。栈满时移除最旧返回记录，再保存当前页；不无限分配。
- 同页重复跳转不入栈、不重建。返回优先关闭当前确认对话框，其次弹出页面记录；空栈返回首页。
- 离页前捕获，根销毁后再设置模型和创建目标页；恢复后完成 layout，再以无动画方式还原合法 scroll。
- 首页切换新筛选时滚动回顶部；返回同一筛选则恢复位置。
- 设备/趋势原点位已不存在时返回首页，不悄悄改成另一点位。
- 原选中告警已恢复时，详情选择当前最高优先级活动告警；没有活动告警则空状态。不会因此确认或静音新告警。
- 同一报告版本恢复滚动；新报告版本回顶部，正文和后台状态不复制进导航栈。
- 不缓存扫描开关、候选写入意图、确认对话框或正在按下的按钮。进入总线探查仍默认关闭，不自动重发 scan/apply。
- 状态只存 RAM，重启恢复当前产品默认态，不新增持久化格式。

## 5. 热区与反馈

保持现有配色、字体、4 px 卡片圆角和信息结构，不做视觉重设计。

- 内容区主要触控按钮高至少 36 px、宽至少 40 px，固定尺寸不随文字、按下态或加载态改变。
- 顶部状态栏仍为 28 px 高，这是明确例外：返回有效热区 48x28，告警入口至少 44x28，限定在状态栏内，不跨入内容区造成重叠。
- 非交互状态 chip、空白容器和装饰标签不得吞掉父级点击。
- 顶部日期、时钟和状态布局在最宽合法标题/状态下检查；标题需要时单行省略，不缩小热区或让文字盖住相邻控件。
- 按下即使用现有 pressed 样式；不新增延迟动画、阴影扩张或全屏转场。
- 报告请求在事件处理完成前进入可见忙状态，使用真正 disabled 状态阻止重复提交；返回可用。结果/失败恢复可操作状态。
- 保持原有标记处理与静音含义，不把变灰表示为告警消失。
- 新状态文案如需新增中文字形，只更新实际需要的字体子集，不更换字体系统。

## 6. 最终测试

无头用例详见 [interaction-cases.md](research/interaction-cases.md)。真实验收完全沿用父任务 `research/acceptance-contract.md` 的数据、负载、样本数和时间起止。

记录优化前、子任务 2 后、最终三组结果；必须说明固件、配置、数据、网络和 Agent 是否一致。软件 near-window 统计只供归因，实体触摸/显示由原始录像验证。

不达标时先定位剩余环节。需要 DMA2D、tickless、I2C 加速、缓存或公共驱动调整时提交下一轮建议，停止扩大范围，不直接修改它们。

## 预期改动范围

| 模块 | 改动目的 |
|---|---|
| `app/velaguard/vg_hmi.c` | 输入周期和有界 sleep |

不改公共树；本任务不改变数据采样、业务模型 tick 或文件 worker 的协议。

## 风险与回退

- 原生惯性停止和 click 的具体事件顺序由当前 LVGL 决定，先写 scripted pointer 测试，不以桌面鼠标直接 handler 调用代替。
- 只回退本任务的输入/手势/导航变更，保留子任务 2 的生命周期修复。
- 如果 10 ms 设置无收益或导致明显调度负担，保留测量证据并保持任务未完成，重新讨论目标与方案；不得暗改为关闭业务线程。
- 热区扩大失败时调整局部布局，不任意修改整屏高度或缩减既有主要工作区。
