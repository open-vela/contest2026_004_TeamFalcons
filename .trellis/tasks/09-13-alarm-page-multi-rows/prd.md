# 告警页多分栏显示与逐告警处理静音

## Goal

多个点位同时告警时,告警页逐点分栏显示,每栏展示点位与摘要,并各自提供标记处理与静音按钮;替代当前只显示单条告警的行为。

## Background / Problem

- 现状:模型层只有单个全局告警槽 `s_alarm`(gui/main/ui/model/vg_model.c:39),`vg_model_set_live` 的晋级守卫(阈值 1733-1749、离线 1794-1810)使同时多点告警只保留最高优先级一条,其余被丢弃。
- 告警页(vg_page_alarm.c)只渲染这一条;`pending_alarm.txt` 由 backend 按单告警写入,任一点恢复即整文件删除。
- 用户要求:多点同时告警时告警页分栏同时显示,分栏内容为点位与摘要,每栏带标记处理按钮和静音按钮。

## Requirements

- R1 告警页:每个活动告警一个分栏,含点位名、摘要(当前值 vs 阈值 + 持续时间;离线显示通信离线 + 持续时间)、标记处理按钮、静音按钮。
- R2 分栏按严重度降序排列(严重 > 离线 > 预警),与 `vg_alarm_kind_rank` 口径一致。
- R3 已确认的交互方案:点选分栏在下方详情区显示该点完整告警详情(规则摘要、类型/当前值/阈值/持续/传感器/状态 6 行指标、历史),默认选中最高优先级分栏。
- R4 标记处理为逐点操作:仅目标分栏状态变为已处理并禁用其按钮,不影响其他分栏。
- R5 静音为逐点操作:仅目标分栏进入已静音状态;状态栏告警 chip 在全部活动告警均被处理或静音后才变暗。
- R6 术语遵循 CONTEXT.md:标记处理只记录已知晓(Acknowledgement != Resolution),分栏保留到恢复条件满足。
- R7 `pending_alarm.txt`:保持单条记录格式与 Agent 契约不变,内容为主告警;全部活动告警恢复后才删除文件。
- R8 首页快捷静音作用于全部活动告警;诊断页维持现状(作用于主告警)。

## Acceptance Criteria

- [ ] AC1 两点同时越限(或一越限一离线)时,告警页出现 2 个分栏,各含点位名、摘要、标记处理、静音按钮。
- [ ] AC2 标记处理其中一栏,该栏显示已处理且按钮禁用,另一栏不受影响。
- [ ] AC3 静音另一栏后,状态栏告警 chip 变暗;仅处理/静音一部分时 chip 保持醒目。
- [ ] AC4 点击分栏,详情区切换为该点的规则摘要、指标行、历史数据。
- [ ] AC5 单点恢复正常后该分栏消失,其余分栏仍在,`/data/velaguard/pending_alarm.txt` 仍存在且内容为剩余主告警。
- [ ] AC6 全部告警恢复后,告警页显示无活动告警,`pending_alarm.txt` 被删除。
- [ ] AC7 `make -C app/velaguard/host_tests test` 全绿;PC 模拟器场景冒烟通过;板端固件编译通过。

## Constraints

- 本地安全环契约不变:告警不依赖 MQTT/Agent;Agent heartbeat 解读 pending 文件的流程不受影响。
- 不新增 Recovering 告警种类;不接蜂鸣器;pending_alarm.txt 不改多记录格式。
- 屏幕为 480x272,最小触高 36px,布局不得溢出。
