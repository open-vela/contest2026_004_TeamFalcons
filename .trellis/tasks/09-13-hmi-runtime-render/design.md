# 页面运行和刷新设计

## 总体原则

保留 UI 单线程和现有模型，不引入通用状态管理框架。先修生命周期，再迁移慢操作，最后减少刷新。各步骤使用前置任务的观察点比较，不能通过降低业务更新频率实现提速。

## 1. 页面对象与导航请求

- `s_content` 继续是 Shell 固定内容宿主，每次建立单独的 `page_root` 子对象，尺寸覆盖宿主可用区域，页面 create 接收 `page_root`。
- 只由 Shell 删除当前 `page_root`。页面原有 DELETE 回调注册在该根上，删除时撤销模型监听、删除页面定时器、清空页面上下文。
- 根的默认背景、边框、padding 和滚动属性由 Shell 初始化一次，避免上一页 flex/grid/滚动状态泄漏到下一页。
- 一次导航请求只保存页面枚举和复制后的必要参数，不保存指向旧页面/栈变量的指针。在 UI 安全调度点提交导航，事件回调结束前不销毁其自身所在树。
- 相同目的页、没有参数或状态变化时不重复创建页面；连续重复点击合并为一次导航。首次首页创建保留现有无虚假返回项的行为。
- 导航实际提交时递增 `page_generation`。后台消费者校验当前页和代次，不能仅以 `lv_obj_is_valid()` 判断对象属于自己。
- 本任务只提供生命周期和可读取代次；导航历史状态由下一子任务实现。

## 2. 日报异步接口

在现有 `vg_ui_backend.h` 中用异步请求/快照接口替换 UI 对同步 `read_latest_report` 的直接调用。原有文件读取和正文处理保留为后台私有 helper，PC 后端和测试 stub 同步适配。

建议固定接口名，便于下一 Agent 使用：

```c
int report_request(bool allow_generate, uint32_t *request_id);
bool report_snapshot(vg_ui_report_snapshot_t *out);
```

`vg_ui_report_snapshot_t` 包含请求 ID、状态版本、状态、错误码、已等待秒数、`path[128]`、`body[1024]` 和截断标志。均为值拷贝；字符串始终 NUL 结尾。状态为 `idle`、`reading`、`generating`、`ready`、`empty`、`error`。

行为约定：

| 操作/情况 | 行为 |
|---|---|
| 页面进入 | 先建立可操作框架，再提交 `allow_generate=false` 的读取；已有活动请求则附着，不重复创建 |
| 点击刷新 | 提交 `allow_generate=true`；仍先读已有有效日报，只有没有有效日报时才使用原有生成请求 |
| 已在 reading/generating | 返回当前 request_id，不重复写 poke 文件、不重复建线程 |
| 无报告且不生成 | `empty`，保留真实空状态 |
| 不支持生成 | 返回明确 unsupported 状态，不伪造正文 |
| 生成等待 | 仍以 2 s 间隔查报告，180 s 超时，时间由单调时钟计算 |
| 离页/返回 | 离页只撤销 UI 订阅/定时器；任务和最后结果由 backend 持有，返回读取真实状态 |
| 文件读取失败 | `error` 和错误码；旧正文如保留必须标明是已有结果，不冒充本次完成 |
| 迟到结果 | 只更新对应 backend 请求；旧页面订阅忽略，不使用旧对象地址 |

使用一个可重复利用的文件 worker，不为每次点击创建线程。线程初始栈预算 8 KiB，优先级保持现有 HMI 默认级别，不提高系统优先级。I/O 缓冲由 backend 拥有，不放入传给线程的调用方栈。

请求入队与结果拷贝只做短临界区内存操作。UI 不等待 I/O 或 join。worker 启动失败返回不可用；不回退为同步读取。

report 页结果检查周期为 100 ms，只读内存版本；正文只在版本改变时渲染。离页根删除时销毁这个定时器。生成中不因每 100 ms 检查而每次重设正文。

本任务不扩大 1024 字节正文上限，不改变 Agent 写报告格式或增加历史报告列表。读取与文件替换相遇时给出错误/重试机会，不宣称已有生成请求一定产生了完整新文件。

## 3. 主告警持久化

模型规则判定仍在原有确定性路径内完成，上屏和告警状态不等待文件 worker。

- 将当前主告警产生的完整正文复制到 backend 的有界持久化请求槽，字段格式沿用现有代码，正文预算 256 字节。
- 请求包含单调递增版本、当前主告警键、是否清理和正文。这里保存当前状态，不替代或合并事件审计日志。
- worker 优先处理主告警请求，再处理报告工作；报告轮询不得用长时间 sleep 独占 worker。
- 由同一个 worker 串行执行清理/写入。执行前检查请求版本；已过期的待执行清理不能在较新告警写入后继续删除。
- 现有 `vg_pending_alarm_write()` 对已有文件直接返回成功，所以主告警换点/换类型时仍需按原有替换流程处理 clear/write，并分别检查返回值。
- 只有当前版本实际成功后才更新已完成版本和抑制重复写入的键。失败保留待处理状态、错误码，以 1 s 间隔重试；有更新版本时处理最新真实状态。
- Agent 正常消费并删除文件后，不因文件不存在而在每次 UI tick 重建同一告警记录；保持现有按主告警键变化触发的语义。
- 无活动告警才发布清理请求；单点恢复但仍有其他活动告警时发布剩余主告警。

允许正在执行的旧文件操作结束，但必须立即处理后续新版本，且不能误将旧操作标为新请求完成。健康存储下请求至完成 <=1 s；超限和失败单独诊断。磁盘永久故障时 UI 继续运行，不宣称已落盘。

## 4. 采集快照一致性

不修改 Modbus 波特率、轮询间隔、重试、失败窗口或规则。保留现有每 1 s 的业务模型入口，图形相关的新计时器不得调用一次业务 tick 以冒充更快刷新。

- 将散落的 `g_live_v/g_live_on/g_live_n/g_live_cycle` 封装为有界完成快照：点表代次、完成轮次、数量、样本值和在线标志。
- 采集线程在锁外完成总线 I/O和本批计算，短锁一次发布完整快照。UI 在短锁中只复制，释放后才执行模型更新和任何文件请求。
- 引入 `vg_live_points_copy_versioned(out, generation)`，在同一次受保护读取中取得点表和代次。旧 `vg_live_points_copy()`/`vg_live_points_gen()` 为兼容保留，不更改 NSH 协议。
- 点表加载/解析在锁外处理，发布 `g_live` 与代次时短锁交换。检查全部原有写入入口，保证新读取锁不是只有读方使用。
- 使用 `(table_generation, completed_cycle)` 去重。表代次改变先导入新点表；旧代次结果不按数组位置写入新表。
- 一致性锁不得覆盖 Modbus、eMMC 或 UI 绘制。沿用最新完成快照消费模型，不新增绘制节流导致的采样丢弃。
- 观测到跳过完成轮次要诊断记录，不能宣称 UI 消费了所有物理轮询。若现有最新快照模式无法满足已批准的安全验收，记录独立缺陷并确认范围，不在本任务静默重构采集引擎。

## 5. 增量更新

保留 `vg_model_on_change/off_change`，补充小范围的结构/历史版本或等价完整比较，不引入通用事件总线。

| 更新源 | 最小刷新 |
|---|---|
| 分钟、日期实际变化 | 对应时钟标签 |
| 网络/采集状态变化 | 改变的状态 chip |
| 点值/质量变化 | 对应点位的值、颜色或质量文本 |
| 点表 ID/顺序/name/unit 变化 | 列表结构或对应显示字段，不能只比较数量 |
| 告警持续时间变化 | 对应摘要/详情，不重建行 |
| 告警成员/排序变化 | 按稳定 ID 调整行，保留可重用对象身份 |
| 选中点的新历史样本 | 当前趋势窗口的数据和必要量程 |
| 阈值/窗口/选点变化 | 一次完整趋势更新 |

- 增加小型文本相等判断 helper，仅在多个页面确实复用时放入现有 widgets 层。样式先比较缓存状态，不在每次通知重新套整套样式。
- 首页去掉 setter 通知后的第二次强制重建。空列表也缓存结构状态，不能每 tick clean/create 空提示。
- 以完整有界 ID 集合或结构版本替代截断字符串签名；32 个合法最长 ID 的尾部变化必须可见。
- 趋势每个真实新样本递增该点历史版本，即使 value 未变。仅告警计时、网络或未选中点改变不能重写当前序列。
- 图表点数和 Y 轴范围仅在变化时设置；使用当前 LVGL 支持的数组更新接口批量填充四条现有序列，最后统一 `lv_chart_refresh()`，数组生命周期至少与页面一样长。
- 保持原有阈值、异常点语义和 60/全部样本窗口，不借性能任务改规则或做插值。
- 一个业务批次最多通知当前页面一次。选择和筛选 setter 在值未变化时不通知；通知期间的页面变更延期到 UI 安全点，避免遍历监听时删除其所在页面。

## 预期改动边界

| 模块 | 预期范围 |
|---|---|
| `gui/main/ui/shell` | 独立根、导航安全提交、页面代次、状态差异更新 |
| `gui/main/ui/model` | 后台异步契约、PC stub、结构/历史版本、批次通知 |
| 当前开放 pages/widgets | 生命周期、异步报告和增量显示；不解锁其他页面 |
| `app/velaguard/vg_ui_backend_board.c` | worker、完整快照、持久化请求 |
| `app/velaguard/vg_point_table.c`、`vg_discover.h` | 配套版本化复制和短锁发布，保留配置/确认协议 |
| `gui/headless`、`app/velaguard/host_tests` | 延迟、并发、生命周期、规则兼容回归 |

只有上述契约确实需要时才调整应用 Makefile 或 helper；不修改公共仓和 `vendor/`。

## 回退边界

按生命周期、后台、增量刷新三个逻辑单元审查。某项优化无收益可撤销本任务该单元，但不恢复失效页面回调。并发、持久化或规则验收失败必须修复或保持任务未完成，不以更低刷新率掩盖。
