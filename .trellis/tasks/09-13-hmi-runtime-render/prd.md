# HMI 页面生命周期与增量刷新优化

## Goal

让现有页面在数据更新和反复切换时保持稳定响应。修复资源生命周期，移除 UI 调用链中的慢文件操作，减少无意义重绘，同时保持已确认点表、采集轮次和告警规则语义。

父任务：`09-13-hmi-ux-performance`。本任务创建时尚未改动任何产品代码。

## Background

统一代码证据见父任务 `research/current-state.md`，具体风险链见本任务 [生命周期与数据流研究](research/lifecycle-dataflow.md)。

- E10-E12：共用 parent 不被删除，DELETE 回调不能随切页释放页面资源。
- E13-E15、E21：重复刷新、截断结构签名和历史更新判定使绘制开销与数据真实性均有改进空间。
- E16-E20、E26：报告和告警文件操作在 UI 链路，跨线程采集数组没有完整快照保护。

## Requirements

| 编号 | 要求 |
|---|---|
| R-R1 | 离页释放页面拥有的监听、定时器和临时对象；重复切页不留失效回调 |
| R-R2 | UI 只处理内存状态，日报扫描/读取/生成请求文件操作移到后台，离页不终止既有生成任务 |
| R-R3 | 后台结果有请求身份和版本，不操作 LVGL，也不回写销毁后的页面 |
| R-R4 | 采集点表代次、完成轮次和数据来自完整快照；已确认表变化不发生错点匹配 |
| R-R5 | 未变化的显示内容不重写；列表结构变化准确，历史新样本同值也能更新 |
| R-R6 | 主告警文件保持现有格式和当前主告警语义；失败可见可重试，上屏不等待存储 |
| R-R7 | 为下一任务提供稳定页面根、结构版本和后台状态接口，不提前更改输入周期或导航交互 |

## Acceptance Criteria

| 编号 | 验收 | 对应需求 |
|---|---|---|
| R-AC1 | 首页/详情/趋势/告警/报告/扫描页往返 200 次，相同页面资源计数回到基线，ASan 检查无失效访问 | R-R1 |
| R-AC2 | 注入 2 s 文件读取延迟时，UI 仍处理按下和返回；离页后迟到结果不修改其他页面 | R-R2、R-R3 |
| R-AC3 | 重复刷新只存在一个报告请求，生成中返回后仍显示该请求真实状态；读取失败与生成超时可区分 | R-R2、R-R3 |
| R-AC4 | 快照并发、表代次变化、完成轮次重复/回绕均有测试；每个被消费轮次只推进一次失败窗口和历史 | R-R4 |
| R-AC5 | 稳定场景下无重复列表重建；空表、长 ID 和同数量换点、改名均正确；一次操作最多一次结构更新 | R-R5 |
| R-AC6 | 新历史样本同值时曲线窗口前进；仅告警持续时间或状态栏改变时不重写趋势序列 | R-R5 |
| R-AC7 | 单点恢复保留其他活动告警，最终恢复才清文件；写失败不标已完成，旧清理不覆盖新告警 | R-R6 |
| R-AC8 | host_tests、板端相近无头 profile、固件构建及阶段性板测通过，交接稳定根/后台/版本接口并给出与基线的分段对照 | R-R1 至 R-R7 |

## Blocked by

- 必须先有 `09-13-hmi-performance-baseline` 的可用观察工具、测试入口和 L0/L1/L2 基线。缺少基线时不先调优再补造优化前数据。
- 用户须另行授权实施本任务。
- L3 若独立受 Agent 挂死问题阻塞，不阻止本任务的 UI/后台回归，但保留最终验收缺口。

## Out of Scope

新的页面功能、手势种类、返回状态设计、输入周期、系统 tick、驱动/缓存改动、扩大点表容量、规则改写、报告协议变更、强制重新生成已有报告。
