# 9/20 前提交：怎么做、只烧一套固件

这份设计给三个子任务共用。父任务本身不改产品代码。

截止日期是 2026 年 9 月 20 日。评委看三样东西：仓库、作品说明、不超过 5 分钟的演示视频。

## 只留一套固件

作品主线是 `velaguard-lvgl`（网络 + 带屏界面 + Agent 都编进同一镜像）。`bash scripts/build.sh` 无参数就是这套。`velaguard` 和旧习惯里的 `net` 也指向它。

带屏固件里已经编进了 Agent。设备 shell 可以执行 `ai_agent`。屏幕负责看，Agent 负责讲。

2026 年 9 月 1 日在开机时同时自动启动界面和 Agent，整机触发断言后卡死。片内静态内存当时大约占用 92.5%。带屏编译里为了省内存，默认不启动 Agent 的定时心跳。因此当前开机路径会跳过自动启动 Agent。这是保护措施，不是改回第二套无屏固件的理由。

真正想给评委看的，仍是一次开机：屏幕起来、网络起来，再启动 `ai_agent --daemon`。第二步用大约 8 小时验证这件事。做成了，视频只烧这一套。做不成，当天停止；视频仍只烧这一套：屏幕拍告警，日报用磁盘上已有文件，Agent 用已经上板过的记录作证据。不要再烧 `velaguard-net`。

不要在开机瞬间同时自动启动这两项。

## 点表和阈值从哪里来

固件不内置演示用的点名、地址和阈值。编译进镜像的组态数组不能再当运行时的数据源。

上位机经调试串口批量下发点表（从站地址、寄存器、倍率、比较方式、预警值、严重值）。板端只做：

1. 收到后先放进候选表，试读一次寄存器。
2. 本机确认后才写入 eMMC（沿用现有 `points.json` / 配置双槽），采集和告警才改用新表。
3. 按点表规则比较实时值；连续读失败则判离线。
4. 告警显示在屏幕上，并写入 `/data/velaguard/pending_alarm.txt`。

没有点表时，首页为空，不编造传感器。Agent 不能改点表。

演示触发仍可用：上位机把某点阈值配成水浸等于 1，再让从站输出 1；或拔掉 RS485。都不需要大模型，断网也要能告警。

点表由仓外上位机 `F:\Project\uppercomputer` 经 ST-LINK NSH 下发（导入 JSON → `vgpoint add`/`set` → `test` → 人点确认 → `apply --confirm`）。竞赛仓脚本 `scripts/vgpoint_host_apply.ps1` 只作无人值守抽检。9/20 不把 GUI 收进专属仓、不新开第三套写入路径。

## 日报文件放在哪里

日报只能由 Agent 生成。屏幕报告页只打开已经写好的 Markdown。

9 月 20 日前提交不做周报。

已经验证过的写入位置是 `/data/velaguard/reports/`。屏幕读取同一目录（`CONFIG_VG_HMI_REPORT_DIR`）。

## 第二步：在同一套固件上试一次 Agent（限时约 8 小时）

`packages/ai_agent` 里已经有带屏编译的特殊路径：启动时不调用 `mallinfo()`（堆占用高时遍历堆可能触发断言）、循环用静态栈、缓冲区缩小、定时心跳默认关闭。

1. 烧录作品主线，确认屏幕正常，点表由上位机写入后告警仍可用。
2. 等界面和网络就绪。
3. 执行 `ai_agent --daemon`。
4. 日志出现 `Agent loop started (HMI fixed buffers)`，整机仍可用。
5. 提问一句实时读数或请它生成日报。日志里要有工具调用，不能写寄存器。
6. 屏幕报告页能打开刚写的日报。

不要打开心跳。失败后不要继续改内部静态内存。

8 小时内做不到：当天停止。不要改烧第二套固件。2026 年 8 月 30 日的日报记录仍可作证据。

## 评委需要听懂的一句话

VelaGuard 跑在 STM32H750B-DK 上：采集、统计、告警在本地完成；点表由上位机下发；板载 Agent 把数据讲给人听。底层改动已作为 7 个公共仓库 Pull Request 提交（持续集成通过）。

视频：一次开机，告警上屏，再提问或出日报。Agent 试验做不成，就拍告警和已有日报，README 写清 Agent 要等界面起来后再手动启动。

## 出了问题怎么退

告警规则改坏：修运行时比较和落盘，不要把点名写回固件。

带屏启动 Agent 再次断言：停止试验，开机仍不自动启动 Agent。评委材料不改成两套固件。

提交前校验 AI 日志，不要改会话文件正文。
