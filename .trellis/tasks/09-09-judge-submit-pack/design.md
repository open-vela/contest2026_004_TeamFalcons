# 技术报告从零重建

## 范围

本设计只覆盖 2026-09-14 用户批准的技术报告重建。既有 README、
分镜和提交操作继续保留在父任务要求中，本轮不执行。

## 内容与证据

以 `docs/submission/REQUIREMENTS.md` 的信息表、章节和已确认口径为输入。
代码、配置、板测原始记录和 GitHub PR 元数据分别证明实现与测试结果。
旧稿不作为证据。每个实测数字注明日期、条件和来源，历史无屏 Agent
结果与带屏自启/工具轮次分开。堆统计出现不合理数据时不据此推断容量。

## 生成流程

报告专用的结构化 Python 内容是唯一正文源，按段落、标题、表格、图片、
引用组织；同时生成 Markdown 与 DOCX。使用 python-docx 编辑官方模板
副本的报告区域，保留基本样式与页面设置，移除其他提交说明、填写提示、
水印。三张图使用 Pillow 重新绘制，字体从本机读取，不新增分发字体。

表格使用原生 Word 表格，引用使用超链接。Word 无界面导出到本次独立
临时目录，检查 PDF 成功后才发布到仓内和 F 盘；不以旧 PDF 的存在判成功。
Windows/WSL 路径显式转换，不把 Linux 路径直接交给 Word。

## 验证与保留

结构检查覆盖必填项、摘要字数、表格、图片、链接和水印；回归测试覆盖
失败导出、路径、模板保护和内容一致性。逐页渲染并人工视觉检查，记录
QA 结果。其他脏文件不修改，模板原件哈希保持一致；不自动提交或归档。
