## 第一步：产品定位的连带调整

Agent 招牌从「故障诊断」换成「点表语义化」后，手册 §1.1 的一句话定位需要跟着动。

现定位：「RS485/Modbus **现场诊断**网关……核心是能自己发起总线实验的板载 AI Agent」

提议新定位：「RS485/Modbus **现场接入**网关……接上一条陌生总线，它自己扫得出、认得懂、说得清」

理由：诊断能力降级为规则库后不再是 Agent 招牌；而「把陌生总线变成看得懂的点表」才是新的核心叙事，且诊断作为规则库能力仍然保留在产品里。

**此项需在最终评审中确认后再落笔。**

## 第四步：改 `CONTEXT.md` 术语表

- 新增 **Register Semantics（寄存器语义）**：一个寄存器所代表的物理量、单位、量纲与正常区间。_Avoid_：data type, word order（那是 Decoded Value 的属性）
- 新增 **Semantic Annotation Session（语义标注会话）**：扫描完成后自动启动的 Agent 会话，用只读工具验证语义假设并产出候选点表
- 新增 **Host Configurator（上位机）**：经 USB CDC 连接的配置期工具，可创作配置但不可激活配置。_Avoid_：PC sidecar, remote console
- 复核 **Manual Profile** 是否仍然需要（手册解析已在 v2 删除，该术语可能已失效）
- 复核 **Candidate Configuration** 的定义是否覆盖新的候选点表
