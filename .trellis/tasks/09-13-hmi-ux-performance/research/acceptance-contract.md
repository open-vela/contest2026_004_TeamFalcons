# 性能与验收契约

本文件是三个子任务的统一口径。所有数值是目标或测试条件，不是当前实测成绩。

## 时间和帧率

| 名称 | 起止与统计 | 门槛 |
|---|---|---|
| 按下反馈 | 实体手指接触到按钮/行首个可见按下状态；按测试组记录全部样本 | P95 <=100 ms |
| 切页响应 | 一次有效点击释放到目标页主体、导航和本地操作可用 | P95 <=200 ms |
| 报告页切入 | 页面框架和真实加载/缓存状态可用；不把网络生成等待混入切页指标 | 同切页门槛 |
| 连续滚动 FPS | 保持拖动或惯性运动窗口内，屏幕实际呈现不同位置画面的次数/秒 | >=30 FPS |
| 滚动帧间隔 | 上述不同位置画面的相邻可见更新时间差 | P95 <=50 ms |
| 软件渲染/提交 | 软件观察点对应阶段耗时，记录单位、时钟粒度和样本窗 | 诊断指标，不能替代前述真实反馈 |

- P95 使用完整组内样本的 nearest-rank：升序后第 `ceil(0.95*n)` 项。各场景分别给结果，不能混合快慢场景掩盖失败。
- 无计时能力时填写未测，不能把配置 16 ms 换算成已通过 60 FPS。
- 软件 FLUSH_FINISH 或 `lv_display_flush_ready()` 表示回调/提交协议完成，不证明面板扫描已完成。
- 静止页没有可见变化时，不要求 30 FPS，也不允许用不断重绘静止页提高分数。
- 记录所有超过 100 ms 的连续运动长帧，注明当时业务。真实采集/告警事件不从统计中任意剔除。

## 实测方法

1. 建议使用 >=120 FPS、优先 240 FPS 的摄像设备，同时拍到手指和屏幕。保留原始帧率、时间戳和测量分辨率；禁止以转码补帧增加精度。
2. 每次回放记录接触、释放、首个反馈及目标页可操作帧号。边界不清时标记不确定样本并重测，不直接删掉慢样本。
3. 滚动使用长列表内容位移辨识真实新画面；系统时间跳字和性能浮层不算新的滚动画面。
4. 无法取得实体接触到显示的证据时，软件测试只能报告软件段延迟。性能基线及整体验收对应条目保持未完成。
5. 只在测试前后或分段边界读取 NSH 统计。默认关闭逐帧打印、录屏辅助浮层和高频串口轮询，避免测量本身改变负载。

## 数据场景

| 数据组 | 内容 | 用途 |
|---|---|---|
| D0 | 无已确认点表，空首页和空告警 | 空状态无重复重建、无伪造点位 |
| D1 | 板上当前已确认点表，记录实际数量和内容版本 | 实际场景对照 |
| D2 | 32 点已确认表，覆盖长 ID、重复显示名、最长合法名称 | 既有容量压力 |
| D3 | 1、3、8 条可展示告警，覆盖严重、离线、预警以及逐点恢复 | 交互及排序 |
| D4 | 32 点后台负载，可包含超过 8 个活动告警 | 检查模型总数和当前 8 行展示规则，不要求新增分页 |
| D5 | 无报告、有效报告、读取失败、生成中、超时和延迟返回 | 异步状态与退出恢复 |

D2/D3 的板端准备必须遵循 `docs/velaguard-host-nsh-protocol.md` 和候选确认技能。编辑、试读、人工确认不可合并自动执行。同总线只允许开发板为主站。无头 fixture 不等同于板端点表已经确认。

## 负载矩阵

| 组 | 运行条件 | 必做动作 |
|---|---|---|
| L0 | 正常采集、无新增交互 | 静止页资源和无变化重绘观察 |
| L1 | 正常采集、网络和遥测保持产品状态 | 首页滚动、筛选、详情往返、趋势选点/窗口 |
| L2 | 断网或 MiMo 不可达，采集正常 | L1 动作、报告加载/失败、告警操作 |
| L3 | 同一固件 Agent 正常生成报告或执行合法只读工具 | L1 动作、报告离页/返回、多告警操作 |
| L4 | 从站失败/恢复和告警状态变更 | 滚动中更新、按下期间恢复/重排、主告警文件核对 |

不能通过更换为无 HMI 固件、关闭产品 Agent、停遥测或停采集来替代 L3。已有 Agent 缺陷可单独报告，但该组不能写为通过。

## 最低样本规模

- 总计至少 200 次有效点击；L1、L2、L3 各不少于 50 次，覆盖主要按钮、点位行和告警操作。
- 总计至少 200 次有效切页；L1、L2、L3 各不少于 50 次，包含首页/详情/趋势/告警/报告往返。
- L1、L2、L3 下，对首页、告警和报告的可滚动内容分别完成 3 段不少于 10 秒的连续运动记录；每段分别计算帧率和帧间隔。
- 30 分钟混合操作；每 5 分钟回到同一静止页面，等待后台结果消费和动画结束，再比较资源。
- 没有足够报告文本或告警行时，在合法测试数据中构造可滚动内容，不通过修改生产容量凑场景。

## 资源与正确性

- UI 对象、页面事件回调、模型监听和页面定时器在相同页面状态下回到预热基线，不随访问次数累加。
- 对堆使用量、最大连续空闲块、各线程栈余量记录实际可获取的指标。重复 5 分钟检查点不得持续单向恶化；发现增长要解释其有界上限并用再次回到稳定状态证明。
- 相同采集完成轮次最多应用一次；点表代次变化不能让旧下标写入新点位。
- 比较 `ge`、`le`、`eq`、无阈值、瞬时失败、持续离线和恢复。单点恢复不删除其他仍活动的主告警。
- 本优化不改变样本窗口、失败门槛、采集间隔或规则优先级。告警从完成样本到模型可见的时延不超过原有一个 1 s 业务 tick 加一帧预算。
- 文件持久化异步化后单独测量完成时延和失败重试；健康存储下应在提交请求后 1 s 内完成。存储异常不能把 UI 成功反馈当作已落盘。
- 已知基线缺陷不能被当作允许回归的理由；首次告警、恢复、确认边界仍以根规则为准。

## 证据包要求

每个实施阶段输出一份实际记录，至少包含：

- 本仓和相关公共 checkout 的 commit、脏改动摘要、构建时间、配置差异及固件标识。
- 板卡、屏幕、已确认点数/数据版本、网络/Agent 状态和具体测试组。
- 原始录像、原始统计、无头截图和命令输出的可复查路径。
- 各组样本数、P50/P95/最大值、滚动 FPS、长帧记录和资源检查点。
- 结果明确分为通过、失败、未测，不将历史成功写成当前结果。

可再生产的临时二进制和帧图放 `.debug/`；任务研究目录保存结果说明和适量证据，不提交 API key、完整 token、AI 会话隐私正文或巨量中间产物。
