# HMI 优化跨任务设计

## 最小行为差距

现有产品已经能显示点位、趋势、告警和报告。本任务补齐可测量性、页面资源生命周期和操作连续性，不建立新的 GUI 框架。

源码身份和事实以 [current-state.md](research/current-state.md) 为准。下列接口为未来实施目标，创建本包时均未实现。

## 架构与所有权

```text
确定性采集线程 -> 完整采集快照 -> UI 模型业务更新 -> 页面差异更新
                                  |
                                  +-> 主告警持久化请求 -> 后台文件操作

触摸设备 -> LVGL 输入处理 -> 用户操作 -> 当前页面
                                           |
                                           +-> 有界后台请求 -> 结果快照

测量层只观察上述路径，不发起总线、网络、确认或告警操作
```

| 所有者 | 责任 | 禁止 |
|---|---|---|
| HMI 主线程 | 所有 LVGL 调用、页面树、导航状态、模型的 UI 侧更新 | 文件扫描、同步等待后台、长时间持锁 |
| 采集线程 | 现有 Modbus 轮询和完成快照发布 | 修改 LVGL 对象、改变总线主站数量 |
| 文件工作线程 | 日报读取、原有日报请求文件写入、主告警文件更新 | 调用 UI 模型或保存 `lv_obj_t *` |
| 诊断读取方 | 复制并格式化统计快照 | 清告警、改配置、每帧打印 |

## 责任分界

### 子任务 1：测量与基线

- 定义并实现可关闭的性能观察接口，所有后续任务沿用。
- 建立独立无头 CMake/CTest 入口，优先使用固件实际 LVGL checkout 和 RGB565；兼容现有桌面模拟器，但不修改它的产品配置。
- 按统一矩阵采集修改前的结果。只加观察点，不提前做后续优化。
- 输出环境、版本、原始样本和未通过项，供后两项比较。

### 子任务 2：运行与刷新

- Shell 创建可删除的独立页面根；页面删除事件真正承担资源释放。
- 后台接口交付有界、带版本的值拷贝，结果生命周期独立于页面指针。
- 对采集快照做一致性保护，保持现有采集频率、1 Hz 模型业务入口和轮次去重语义；仅合并绘制通知，不新增丢样策略。
- 建立结构、内容和历史版本，修复重复渲染入口。稳定对象身份由本任务建立，跨触摸手势的状态冻结由子任务 3 完成。

### 子任务 3：交互与整体验收

- 在子任务 2 的生命周期基础上实现导航状态保存/恢复。
- 调整输入读取和主循环休眠上限，不改系统时钟或设备坐标配置。
- 处理按下目标、滚动取消、动态结构变更和异步忙状态。
- 以子任务 1 的同条件数据完成最终真机对照。

## 必须保持的接口

- `vg_nav_goto`、`vg_nav_back` 保留为调用入口；状态捕获和恢复在 Shell/页面内部完成。
- 点表 NSH 协议、已确认表格式、`pending_alarm.txt` 正文及 MQTT 格式不变。
- 现有模型变更订阅保留，允许内部合并同一批更新和增加版本查询，不引入通用消息总线。
- 业务结果只能按稳定点位 ID 关联。数组位置、显示名称和旧页面地址不能作为异步身份。
- 现有日报按钮语义不变：有有效报告时重新读取；没有报告才触发当前已支持的生成请求。不新增强制再生成或历史报告管理。

## 新增内部契约

详细字段、容量和错误语义由各子任务 `design.md` 定义，本表用于检查交接是否一致。

| 契约 | 创建者 | 使用者 |
|---|---|---|
| 可关闭统计、`vghmi perf` 诊断读取、近窗样本标识 | baseline | 后两项和人工验收 |
| 页面根生命周期及页面代次 | runtime-render | 所有页面、导航恢复、异步结果消费 |
| 日报请求/状态/结果拷贝接口 | runtime-render | report 页面、交互状态测试 |
| 采集快照的表代次和完成轮次 | runtime-render | UI 模型、去重回归 |
| 点位集合版本、历史版本 | runtime-render | 首页、告警、趋势及导航失效处理 |
| 有界导航状态记录、按下目标记录 | touch-acceptance | Shell、可操作列表 |

## 显示和内存策略

- 保持 RGB565、现有两块帧缓冲、DIRECT 绘制、16 ms 刷新配置。
- 只保留当前页面对象树；保存返回状态而不缓存所有页面。
- 不引入全屏截图转场、透明全屏遮罩、模糊、复杂动效或新的图片资产。
- 文本和颜色变化才修改对象；图表数据批量更新后统一刷新。
- 对静态内存、线程栈和峰值堆分别记账，不只比较空闲堆总量。
- 不通过关闭采集、网络或 Agent，缩短历史、减少点位、忽略告警来满足性能门槛。

## 安全与现状差异

根 `AGENTS.md` 优先于本包引用的手册、旧技能说明和历史任务。

- 告警技能中的固定约 200 ms 一轮、约 1 s 离线描述不能用于当前多点验收。当前 9600 波特率整轮耗时随点数和重试变化，必须记录真实轮次。
- 状态栏已有 `AUD` 和 MQTT 状态映射到 `MiMo` 的历史实现。本优化不得借这些名称增加声音或恢复 MQTT AI Bridge；真实状态含义调整由对应已有任务负责。
- 当前源码没有在本次只读核查中证明完整的自动告警跳页路径。验收须单独测量已有要求；不能把静态技能说明当作已经成功的运行证据。
- 屏幕上已有确认路径不能成为跳过 `vgpoint test` 后人工确认的依据；本任务不重新设计点表应用权限。

## 失败、回退和扩展

- 统计缺样、串口不可用、无高帧率录像、Agent 崩溃都必须写明证据缺口；不能填入推测成绩。
- 各子任务提交可独立审查的变更。后续回退只作用于其自身提交或改动，不能恢复用户或其他 Agent 的未提交文件。
- 统计关闭后保持相同业务行为；后台线程启动失败时显示不可用状态，不回退为 UI 同步 I/O。
- 如果基线暴露必须改动公共驱动、系统节拍或缓存策略的瓶颈，记录独立建议并重新确认范围。当前任务包不授权这些修改。
- 页面清理等安全问题即使原基线有缺陷，也必须修复并复测，不能以回退有缺陷路径作为性能优化交付。
