# 运行时点表、上位机写入、本地告警上屏

所属父任务：`09-09-pre-920-score-play`。

固件不内置演示点表。点表和阈值由上位机批量写入。带屏 Agent 试验要等本任务在开发板上通过。

## 目标

板端按已确认点表执行告警。点表由上位机经 `09-10-host-nsh-vgpoint` 写入 eMMC。本任务在那张表上比较阈值或离线，告警页能看到，并留下待处理告警文件。屏幕读日报的目录与 Agent 写入目录一致。

动手顺序：先完成 `09-10-host-nsh-vgpoint`（命令、落盘、采集改读已确认表），再做本任务的告警比较与上屏。

## 要做到什么

1. 消费 `09-10-host-nsh-vgpoint` 写出的已确认 `points.json`（含比较方式、预警值、严重值）。本任务不实现 `vgpoint` 命令和上位机脚本。
2. 周期采集和首页舰队只读已确认表（由通信任务切源）。没有点表时首页为空。
3. 更新实时值时按规则比较。删除按点名称识别水浸和烟雾的代码。
4. 按已生效表触发超阈值，或拔掉从站，告警页能显示，并写入 `/data/velaguard/pending_alarm.txt`。
5. 屏幕报告页读取 `/data/velaguard/reports`。

## 本次不做

开机启动 Agent、Windows 图形配置软件、在屏幕上编辑点表、周报。

## 怎样算完成

- [ ] 通信任务写入并确认后，超阈值或离线能在告警页看到（不插网线）
- [ ] 设备上能列出 `/data/velaguard/pending_alarm.txt`
- [ ] 报告页打开 `/data/velaguard/reports`
- [ ] `bash scripts/build.sh` 编译通过
